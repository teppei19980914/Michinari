# 問題修正スキル

## 手順

1. 問題のレポートや指摘事項を確認する
2. **情報源の選定（必須）** — 調査が必要な場合は CLAUDE.md「情報源の信頼性ルール」に従い、公式ドキュメント・公式リポジトリを最優先で参照する。推測ベースの実装は禁止
3. **設計影響の判断** — 新しい入力経路・権限境界・外部連携が発生する場合は、修正前に `/threat-model` を実行
4. 該当するソースコードを特定・修正する
5. テストコードを必ず追加・修正する（**セキュリティテストも含む**）。カバレッジ目標・除外条件は `CODING_RULES.md`「テストカバレッジ」を参照
6. **観点別レビュー** — 変更内容に該当するものを並列実行（Task tool で同時起動）。無関係な観点まで毎回全起動するとコストが嵩むため、変更範囲に応じて絞る。判断に迷う場合・セキュリティに関わる変更の場合は広めに起動する
   - `auth-reviewer` — 認証/認可/セッション/権限を扱う変更時
   - `injection-reviewer` — DB操作/外部コマンド/ファイルパス操作を扱う変更時
   - `xss-reviewer` — フロントエンド/HTML出力を扱う変更時
   - `secret-reviewer` — 環境変数/認証情報/ログ出力に関わる変更時
   - `dependency-reviewer` — 依存パッケージを追加/更新した時
   - `performance-reviewer` — ループ/DB問い合わせ/描画処理を変更した時
   - `dry-reviewer` — ロジック/定数/IDを追加・変更した時、または既存関数が肥大化した時
   - `style-reviewer` — 新規ファイル追加時、または命名/コメントに関わる変更時
   - `test-coverage-reviewer` — ロジックの追加/変更を伴う実装変更時
7. 指摘された HIGH 以上の問題は全て修正する
8. コミット前チェックを実施（以下すべて）

## 横展開チェック

- 修正した問題と同じパターンが他ファイルにないか検索
- テストコード内で旧文言を検索し全て新文言に修正
- 共通処理の変更は関連する全ファイルに横展開

## コーディングルールチェック（エージェントで自動化される部分以外）

- **判定基準は `CODING_RULES.md` を参照** — 詳細ルールは本スキルに複製しない
- **多層防御は各エージェントが担当** — `dry-reviewer`（重複）/ `style-reviewer`（命名・コメント）/ `label-checker`（ハードコード文言）
- 本スキルでは指摘の修正漏れがないかのみ確認する

## セキュリティチェック（エージェントで自動化される部分以外）

- **多層防御は各エージェントが担当** — 本スキルでは「修正漏れがないか」を確認
- **セキュリティテスト**: 以下を必ず追加
  - 認可境界テスト（他ユーザーのリソースアクセス試行）
  - 不正入力テスト（SQLi/XSS payload, 巨大入力, Unicode正規化）
  - 認証バイパス試行
- **新規依存を追加した場合**: `dependency-reviewer` を必ず実行

## パフォーマンスチェック

- ループ内DB問い合わせ禁止（一括取得→メモリ上フィルタ）
- 描画オブジェクトのキャッシュ
- 不要な再描画の抑制
- 独立した非同期操作の並列化

## ドキュメント更新

変更内容に応じて該当ドキュメントを更新:
- 仕様変更 → `SPECIFICATION.md`
- 設計変更 → `DESIGN.md`（セキュリティ設計セクション含む）
- 要件追加 → `REQUIREMENTS.md`
- 運用手順変更 → `OPERATIONS.md`
- 置き場所/命名規則の変更 → `CODING_RULES.md`
