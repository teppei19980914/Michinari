### 6.5 SC-06 日次報告

**構成**

画面を上下2段に分割する。上段を実績入力、下段をAI対話とする。画面上部に所要時間の目安（「3分で終わります」）を表示する（1.1（改28）、記録画面改善タスク）。

着手中（ACTIVE）の目標が2件以上ある場合、画面上部に目標タブを表示し、対象目標を1件ずつ選択して切り替える（目標設定画面のカテゴリ選択と同様、選択肢は着手中の目標に限る）。実績入力・日記・AI対話は選択中の目標の種別（資格試験／読書／仕事）に応じた内容のみを表示し、他の目標の入力欄は表示しない。ただし下書き値はタブの選択に関わらず全目標分をローカルに保持し続けるため、タブを切り替えても入力内容は失われない。着手中の目標が0〜1件の場合はタブを表示せず、従来通りその目標の内容をそのまま表示する。

確定（finalize）はカテゴリ（資格試験／読書／仕事）ごとに独立している（1.1（改13））。あるカテゴリの確定ボタンを押すと、そのカテゴリの実績・日記のみが確定済み（報告済）となり、そのタブは以降そのセクションのみ読み取り専用表示に切り替わる。他カテゴリの確定状態には影響せず、引き続き入力・確定できる。当日中に着手しているすべてのカテゴリが確定済みになった時点で、初めてダッシュボードへ遷移する。

本画面を開いた時点で、着手中の全カテゴリが既に確定済みの場合、または対象日が入力可能期間（当日または前日、7.2）を過ぎている場合は、日次報告閲覧（SC-08）へ自動転送する（1.1（改20））。遷移元（ダッシュボード6.1・カレンダー6.4）は対象日が入力可能期間内かのみを判定し、「まだ報告すべきカテゴリが残っているか」の判定は本画面に集約する。判定に必要な着手中の目標・書籍・案件は本画面のみが取得しているためである。入力可能期間を過ぎた日で転送するのは、入力させたうえで確定時にエラー（14章 BACKDATE_LIMIT_EXCEEDED）となり入力内容が失われるのを防ぐためである。

**ゼロ記録（「今日は何もしていない」ボタン、1.1（改28））**

画面上部（目標タブの上）に「今日は何もしていない」ボタンを表示する。対象は、その日ACTIVEなのに一度も操作していない（未入力）カテゴリのみとし、既に進捗のみ登録済み（実データがある）カテゴリ・報告済みのカテゴリは対象から除外する。全カテゴリが対象外（未入力カテゴリが無い）の場合はボタン自体を表示しない。

押下すると確認モーダルを挟み（取り消せない操作のため）、承認すると対象カテゴリを実績・日記とも空のまま確定する（資格試験：完了量・投下時間ともに未入力のまま確定、読書・仕事：想起・業務内容とも未入力のまま確定）。これは通常の確定処理と技術的に同一であり、実績が1件も無い状態での確定を拒否しないためゼロ記録として成立する。確定後の記録状態は「報告済」とする（7.2の状態遷移における「報告一式を入力」と同じ終着点として扱う。翌日以降に再入力を促さないため）。

確定後はダッシュボードで表示している日種別に応じて次のいずれかをトースト表示する。

| 日種別 | 表示文言 |
| --- | --- |
| PLAN（計画日） | 「記録しました。明日また開いてください」 |
| BUFFER・OFF（バッファ日・除外日） | 「今日はお休みの日です。休むことも計画のうちです」 |

ゼロ記録の確定はAI対話（`/chat`・`/reading-chat`・`/work-chat`）を一切呼び出さない。当日中に着手している全カテゴリが（ゼロ記録も含めて）確定済みになった場合のみダッシュボードへ遷移する規則は、通常の確定と共通（上記「確定処理」参照）。

ゼロ記録の日もカレンダー・ダッシュボード上は「報告済」として扱われ、連続記録日数・報告率の算出（13章）にもそのまま反映される（record_serviceの確定状態列のみで判定するため、実績行の有無を問わない）。

**実績入力（上段、資格試験目標選択時）**

進行中の教材のうち、当日が学習期間内（開始日〜締切）のものを行として表示する。開始日前の教材は表示しない（先行着手した内容は「本日の行動・所感」に自由記述する）。この絞り込みはSC-01の本日のノルマ・SC-07にも共通で適用される。

上記の目標タブにより、この一覧には選択中の1目標の教材のみが含まれるため、目標名の見出しは表示しない（ダッシュボードSC-01も1.1改14で同じ目標タブ方式に変更されたため、目標名の見出しによるグルーピング表示は行わない）。

| 列 | 内容 |
| --- | --- |
| 教材名 | 表示のみ |
| 現在周回 | 表示のみ。「2周目 / 全3周」の形式 |
| 本日の目標 | 算出された日次ノルマを表示 |
| 時間枠ごとの投下時間 | 後述「時間枠ごとの投下時間の入力」を参照 |
| 投下時間（合計） | 表示のみ。時間枠ごとの入力値の合計を自動算出 |
| 完了分量 | 数値入力 |
| 周回 | 数値入力。既定値は現在の周回数 |
| 品質指標 | 教材の設定方式に応じた入力欄。任意 |

**時間枠ごとの投下時間の入力（R-14、R-86）**

投下時間は教材ごとに1つの欄で入力するのではなく、**教材の行の中に、その目標が配分している時間スロットごとの入力欄を並べて**入力する。教材の投下時間はこれらの合計として自動算出し、実効速度の算出にはこの合計を用いる。

| 項目 | 内容 |
| --- | --- |
| 表示するスロット | 当日の曜日に該当し、かつ選択中の目標がリソース配分を設定しているスロット |
| 初期値 | リソース配分の設定値を、そのスロットに適合する教材へ按分した値（ロジック・プロンプト編9.2） |
| 変更の扱い | 入力値の変更はその日の実績としてのみ保存し、リソース配分の設定値（マスタ）は変更しない |
| 未配分スロットの追加 | 「他の時間枠を追加」操作により、配分していないスロットを行に追加して入力できる。予定外の空き時間に学習した分を記録できないと、投下時間が実態より小さく計上され実効速度が過大に算出されるため |

全スロットの入力欄が空欄の場合、その教材の投下時間は「未入力」として扱う（0分ではない）。未入力の実績は実効速度の算出対象から除外される（ロジック・プロンプト編8.4）。

品質指標の入力形式は以下とする。

| 方式 | 入力形式 |
| --- | --- |
| 客観正答率 | 0〜100の数値 |
| 自己採点得点率 | 0〜100の数値 |
| 主観的手応え | 5段階の選択（内部的に20/40/60/80/100へ変換） |

**日記記述（上段下部、資格試験目標選択時）**

「今日学んだこと・理解したこと」欄（1.1（改30））。資格試験の日記入力は、利用者が入力先に迷わないよう、この1欄に集約した（従来の質問2問と「自由に書く」欄は廃止）。振り返りセクションでテーマ別にまとめる対象もこの欄である。任意入力で、空のまま確定してもよい。プレースホルダには、印象に残った問題・詰まった点・理解できた内容をそのまま書くよう例示する。

| 項目 | 内容 |
| --- | --- |
| 今日学んだこと・理解したこと | 複数行テキスト。保存先は`diary_learned`。プレースホルダに記述例を提示 |

既存の日記本文（`diary_body`、旧仕様の質問形式・自由記述で保存されたもの）は、入力欄には表示せず「以前の日記本文」として読み取り専用で表示し、保存時にはそのまま引き継ぐ（記録を失わないため）。新規入力では`diary_body`は空で保存する。日次フィードバックのプロンプトは「今日学んだこと・理解したこと」を先に、旧本文を後ろに配置する（ロジック・プロンプト編17.2）。

各記述欄の上部に、直近の記録日の本文冒頭（100文字程度。資格試験は「今日学んだこと・理解したこと」を優先し、未入力の旧データのみ本文を使う）を「前回はこう書いていました」として薄く表示する（前回の記録が無ければ非表示。クリックで全文展開）。対象は「前日」に限らず、記録がある直近の日まで遡って探索する。あわせて、記述欄の近くにWindowsの音声入力（Win + H）で入力できる旨を小さく案内する（案内文の表示のみ。音声認識機能自体は実装しない）。

日記欄は上記の目標タブに連動し、選択中の資格試験目標についてのみ表示する（読書目標は後述の想起入力が同じ役割を果たすため、日記欄の対象外）。当日のノルマ有無に関わらず選択中の目標がACTIVEであれば表示し、先行着手した内容を自由記述できる逃げ道を維持する。

**AI対話（下段）**

チャット形式の対話領域とする。初回の応答は、実績入力および日記の内容を確定して送信した時点で生成される。

対話は複数往復可能とする。対話終了後、確定操作により報告が確定する。

同一カテゴリの目標が2件以上同時進行している場合、AI対話（会話・プロンプト・履歴のいずれも）は選択中の1目標のみを対象とする（1.1改15、未決事項L-07の解消方針転換）。目標タブを切り替えて別の目標を選択した場合、実績入力・日記と同様にAI対話も選択中の目標分のみへ切り替わる。以前の版（改13以前）はカテゴリ単位で1本の会話を共有し、複数目標の状況をまとめて1回の応答で返す方式だったが、目標ごとに独立した会話・応答へ変更した。

**AIが参照した情報の開示・送信内容への不安の解消（非エンジニア向けエラー表示改善、2026-09-19）**

対話領域に、直近の送信でAIへ渡した情報の種別を折りたたみ（既定は閉じた状態）で表示する。展開すると「目標の情報」「今日の記録」「直近の週次要約」（資格試験のみ「教材の進捗」も）の一覧が表示される。プロンプト全文は表示しない（長すぎて逆に不安を招くため）。送信欄の近くには「送信されるのはこのPCの中の記録だけです。外部に保存されることはありません」を常時表示する。

**AI未設定時の案内**

AI接続が未設定（設定画面で未認証）の状態でAI対話・レポート生成（総括レポート、月次報告・半期評価を含む）を開いた場合、エラーではなく「この機能を使うには、AIの接続設定が必要です。設定しなくても、記録や閲覧はそのまま使えます」という案内と、設定画面へのボタンを表示する。実績入力・確定・記録の閲覧はAI未設定でも通常どおり行える。

**今日の一言のみ例外（S-4 4-1、2026-09-20）**：今日の一言はGET時に自動生成する設計（DSH-03）のため、上記の「案内表示」ではなく、AI呼び出し自体を行わず固定のねぎらい文言（ロケールファイル外部化）を表示する。DBには保存せず、AI設定後に再取得すると通常のAI生成へ自動的に切り替わる。

**確定処理**

確定（資格試験／読書／仕事の各カテゴリの確定ボタン）により、そのカテゴリについて以下が実行される。

1. 実績数値および日記本文（資格試験のみ）を変更不可として保存
2. 対話履歴を保存
3. 当日・当該カテゴリの記録状態を報告済に変更
4. 当日中に着手している全カテゴリが報告済になった場合のみダッシュボードへ遷移。他に未確定のカテゴリが残る場合は同じ画面に留まり、確定したカテゴリのタブのみ読み取り専用表示に切り替わる

確定前の下書き（実績入力・日記・対話履歴）は、画面（ページ）の外に保持し、確定するまで一切サーバへ保存しない（16.7）。従来はページ単位で保持していたため、確定前に別の画面へ移動すると入力内容が失われていたが、アプリ全体で共有する保持領域へ移したことで、別画面へ移動して戻っても同一セッション内であれば入力内容が復元される（1.1（改28）、記録画面改善タスク）。ブラウザを閉じる・再読み込みすると下書きは失われる（サーバへの下書き保存は日次記録の不変性の設計上行わない）ため、その場合のみブラウザ標準の確認ダイアログで警告する。アプリ内遷移（別画面への移動）そのものはもはや入力内容を失わないため、警告なしで移動を許可する（従来あった「移動しますか？」の確認モーダルは撤去した）。

**AI応答が得られない場合**

AI基盤が利用できない場合も、確定操作を許容する。この場合、対話履歴は空となる。

**読書目標の実績入力（REP-13、REP-14）**

進行中の読書目標を選択している場合、実績入力（上段）に書籍ごとの想起欄を表示する（上記の目標タブにより資格試験目標の教材行とは排他表示となる）。

想起欄も資格試験の日記欄と同様、質問への回答形式へ再構成した（1.1（改28）、記録画面改善タスク）。質問（固定2問）と「自由に書く」欄（従来の想起欄。ラベルを変更しただけで役割は同じ）を1画面に併記し、いずれか1つに入力があれば確定できる（従来の「想起本文は必須」の実質を、質問群のいずれかへの入力必須へ置き換えた）。

| 項目 | 内容 |
| --- | --- |
| 書名 | 表示のみ |
| 質問1 | 「今日読んだ中で心に残った箇所は？」への回答欄。複数行テキスト。任意 |
| 質問2 | 「自分の仕事や生活とつながると感じたことは？」への回答欄。複数行テキスト。任意 |
| 自由に書く | 複数行テキスト。自由記述（旧・今日読んだ内容の想起欄）。プレースホルダに「今日はどこまで読みましたか。印象に残ったことは何ですか」等の記述例を提示 |
| 時間枠ごとの読書時間 | 資格試験の「時間枠ごとの投下時間の入力」と同一の仕様（表示するスロット・初期値・その日限りの変更・未配分スロットの追加）。任意 |
| 読書時間（合計） | 表示のみ。時間枠ごとの入力値の合計を自動算出 |
| 現在ページ | 数値入力。任意。0以上、総ページ数以下 |

保存する想起本文（`recall_body`）は日記欄と同じ規則で結合する（質問回答は「【質問文】\n回答」形式、末尾に「自由に書く」欄をラベルなしで連結）。質問に触れず「自由に書く」欄だけを使った場合は従来と同じ本文がそのまま保存される。数値実績（現在ページ・読書時間）の入力は必須としない（R-65）。想起欄（質問・自由記述のいずれか）のみの入力でも確定できる。

想起欄の上部に「前回はこう書いていました」ヒント、近くにWindows音声入力の案内を表示する（日記欄と同じ仕様、1.1（改28））。

ページに関する入力欄は「現在ページ」1つだけとする（1.1改19）。従来あった「読んだページ数」は廃止した。利用者がその日に読んだページ数を毎日記憶していられないという実際の利用上の問題があり、かつ読書は定量的な進捗管理を行わない目標（R-71）であるため、投下量の指標を保持する意味がないためである。現在ページは画面上の進捗表示のためだけに用い、評価の対象とはしない（下記のAI対話への差し込み情報を参照）。

読書目標で記録した時間は、実効速度・完了予測日の算出には用いない（読書はこれらを持たないため。R-71）。集計・表示・AIへの文脈提供にのみ用いる。

AI対話（下段）は資格試験と共通のUI構成を用いるが、通信先は別エンドポイント（`POST /records/{date}/reading-chat`）とし、読書用プロンプト（REP-14、17.6参照）で生成する。会話・対話履歴は用途ごと・目標ごとに分離されており（`ai_conversation`の`scope`＋`goal_id`、および`chat_message.purpose`＋`goal_id`によるフィルタリング。データ構造編5.4・5.5、ロジック・プロンプト編21.1、1.1改15）、資格試験目標と読書目標が同日に両方進行中でも、また同カテゴリの目標が2件以上進行中でも、互いの対話内容は相手のプロンプトに混入しない。

**仕事目標の実績入力（REP-15、REP-16）**

進行中の仕事目標を選択している場合、実績入力（上段）に案件ごとの業務記録欄を表示する（上記の目標タブにより資格試験・読書の入力欄とは排他表示となる）。

業務内容欄も読書の想起欄と同様、質問への回答形式へ再構成した（1.1（改28）、記録画面改善タスク）。

| 項目 | 内容 |
| --- | --- |
| 案件名 | 表示のみ |
| 質問1 | 「今日いちばん時間を使ったことは？」への回答欄。複数行テキスト。任意 |
| 質問2 | 「気になっているが手をつけていないことは？」への回答欄。複数行テキスト。任意 |
| 自由に書く | 複数行テキスト。自由記述（旧・本日の業務内容欄）。プレースホルダに「今日はどのような業務に取り組みましたか」等の記述例を提示 |

読書と異なり、ページ数のような数値項目は持たない（要件定義書6.11本文「構造化フィールドは持たない」という設計判断）。保存する業務内容（`body`）は日記欄・想起欄と同じ規則で結合し（質問回答は「【質問文】\n回答」形式、末尾に「自由に書く」欄をラベルなしで連結）、質問・自由記述のいずれか1つの入力でも確定できる（従来の「業務内容は必須」の実質を、質問群のいずれかへの入力必須へ置き換えた）。業務内容欄の上部に「前回はこう書いていました」ヒント、近くにWindows音声入力の案内を表示する（日記欄と同じ仕様）。

AI対話（下段）は資格試験・読書と共通のUI構成を用いるが、通信先は別エンドポイント（`POST /records/{date}/work-chat`）とし、仕事用プロンプト（REP-16、17.8参照）で生成する。会話・対話履歴は読書と同じ仕組み（`ai_conversation`の`scope`＋`goal_id`、`chat_message.purpose`＋`goal_id`）で分離されており、資格試験・読書・仕事の各目標が同日に進行中でも、また同カテゴリの目標が2件以上進行中でも、互いの対話内容は相手のプロンプトに混入しない。

**チームメンバーの編集（GOL-20、2026-09-23、R-93）**

進行中の仕事目標がある場合、業務記録欄の下にその案件のチームメンバー一覧を表示する（着手中の仕事目標が複数ある場合は案件ごとに1ブロックずつ表示する）。表示内容・追加/編集/無効化/削除の操作は目標詳細画面（SC-03）の案件情報タブと完全に同じであり、同じデータを参照する（同一のAPI・データソースを用いるため、片方の画面での変更はもう片方の画面でも常に反映される。専用の同期処理は設けない）。
