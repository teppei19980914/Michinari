# 開発Todo：月次報告・半期評価の出力フォーマット整理

本書は、仕事目標（WORK）の月次報告・半期評価について、①自由記述の各節を「項目名：内容」のテキスト形式で記述するルールの追加、②達成度（1〜5）のスケール反転の修正、③出力本文（`body`）の見出しを`##`から`【】`形式へ変更し達成度の節を除外、の3点を行う開発作業の正（Single Source of Truth）である。新規フェーズは起こさず、既存Phase22・23（月次報告・半期評価）の修正として扱う。作業は `dev/2026-11-01` で行う。

## 0. 経緯・決定事項

利用者から、目標詳細画面の月次報告の出力フォーマット案（【この期間の目標】【業務内容（案件内容）】【目標の達成状況と進捗に関する振り返り】【来月の目標】【報告・連絡事項】の5節、各自由記述欄は「：」区切りで複数項目を列記）が提示され、まず検証のみを別セッションで実施した。検証の結果、以下が判明している。

- 提示された5つの見出し文言は、既存フォームのラベル（`ja.json`の`goals.workReport.targetGoalTextLabel`="この期間の目標"等）と完全一致しており、既存画面を土台にした変更要求である
- 提示フォーマットには「達成度」の節が無い
- 「：」区切りのテキスト形式ルールは、1案件内で複数のテーマ・タスクが並行する場合の記述形式（利用者が明言：「こちらの内容は1案件内での1月次報告内容です」）であり、複数案件（複数goal）を1通に束ねる話ではない（既存R-80「複数案件を横断した1通に集約しないこと」はそのまま維持）
- 利用者から達成度の基準定義が「5が最高評価（121%以上）・1が最低評価（0〜59%）」という逆向きの対応表で提示された。現行実装（`app/init/prompt_texts_work.py`、要件定義書R-78）は「1が最高評価・5が最低評価」であり、提示内容と逆転している → **修正が必要と確認済み**

上記を受け、以下をAskUserQuestionで確認し確定した。

| # | 決定 | 値・理由 |
| --- | --- | --- |
| D1 | 達成度の扱い | **出力本文（body）からのみ除外する。** フォーム入力欄・`achievement_score`列・AIによる判定自体は維持する（人事考課の裏データとして使い続けるため、利用者が明言） |
| D2 | 半期評価への横展開 | **半期評価にも同じ変更を適用する。** CLAUDE.mdの「仕様変更は基本的に全画面へ横展開する」方針（[[horizontal_expansion_policy]]）に基づく。達成度スケールの反転は月次・半期で判定基準を共有しているため、この部分は横展開が前提だった |
| D3 | 見出し`【】`化の対象 | **ダウンロードされる本文（body）のみ。** AI応答のパース契約の見出し文字列（`## 業務内容の要約`等）、画面の入力欄ラベルは変更しない（入力欄ラベルは既に提示フォーマットの文言と一致済みのため変更不要） |

### 1.4 既存機能への横展開（同じ問題の有無を確認）

| 項目 | 状況 | 対応 |
| --- | --- | --- |
| 達成度スケールの基準表（1〜5の意味） | 月次報告・半期評価の両方のプロンプト文面に同一内容が重複して存在（`prompt_texts_work.py`内の2箇所） | 両方に反転を適用（D2）。基準表の文言はDRY上1箇所に共通化できないか確認したが、両プロンプトは独立した`prompt_template`の初期投入文面であり、既存の設計判断（データ構造編、purposeを分離）により共通化していない。本件もその既存方針に従い両方へ同内容を反映する |
