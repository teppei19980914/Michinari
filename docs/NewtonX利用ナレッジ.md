# NewtonX利用ナレッジ（他プロダクトとの共有用）

NewtonX（開発キット `newtonx_adk` 0.10.5 とその API）を、ミチナリのAIアシスタント開発で実機検証した結果をまとめる。
**他プロダクトでNewtonXを使う際は、まず本書を読む。** 記載の数値は 2026-10-04〜10-07 の実機検証によるもので、NewtonX側の仕様変更で変わりうる。

- 対象：`newtonx_adk` 0.10.5（`myvenv/Lib/site-packages/newtonx_adk/client.py`）
- 検証の方法：一時DB（`MICHINARI_DATABASE_URL`）を使い、利用者の本番データに触れずに実機の NewtonX へ送信。作成したチャットは、後始末で削除。
- 認証情報（PAT等）は `~/.newtonx/config.json` にあり、本書にも記録しない。

## 2. できること・できないこと（ADK 0.10.5）

| 操作 | ADK の関数 | 結果 |
| --- | --- | --- |
| 認証状態の確認 | `AuthManager.is_authenticated()` | 設定ファイルの PAT で `True` |
| アシスタント一覧 | `get_assistants()` | 21件（ミチナリ環境）。`uid`・`name`・`model`・`type`（`system`／`group`／`company`） |
| アシスタントの作成 | なし | **できない**（ADK に無い。API の生の存在は未確認） |
| ナレッジ（資料）の一覧 | `get_assistant_knowledge(uid)` | 読めるものは件数を返す。**権限が無いと 403**（9件で発生） |
| ナレッジの登録・削除 | `add_assistant_knowledge` / `delete_assistant_knowledge`（docx/pdf/txt 等、16MB以下） | ソース上は存在。ミチナリでは登録は未実施 |
| フォルダの作成・一覧 | `create_folder`・`get_folders` | 作成・一覧は可 |
| フォルダの削除 | なし | **できない**（手動で削除） |
| チャットの作成（フォルダ指定） | `create_chat_in_folder_by_name(assistant_uid, folder_name, title)` | フォルダ名で既存を流用し、無ければ作成。同名フォルダは増えない |
| 送信 | `send_message(chat_uid, message, knowledge_search, web_search)` | 送信内容は**今回のメッセージ1件だけ**（`role: user`） |
| チャットの削除 | `delete_chat(chat_uid)` | **戻り値（True/False）は信頼できない**（後述） |
| チャットの詳細 | `get_chat(chat_uid)` | 未検証 |

## 3. 検証で分かった挙動（重要）

### 3.1 文脈は引き継がれない
- 同じチャットで名前を伝えても、次の質問では覚えていない（2試行で不成立）。アシスタントは「覚えました」と答えても、次の回答では覚えていない。
- 別チャットとの分離は確認済み（対照実験）。
- **設計への含意**：会話の文脈が必要なら、アプリ側で直近の質疑をプロンプトに含める。NewtonX の履歴には頼らない。

### 3.2 チャットの削除
- `delete_chat` は、削除に成功しても `False` を返すことがある（ADK はステータス200のみを成功と判定する実装）。
- **確認方法**：削除後にフォルダのチャット一覧（`get_folder_chats`）を再取得し、そのチャットが残っていないかで判定する。
- 削除済みのチャットへ送信すると `APIError`（メッセージに `404`）。

### 3.3 ナレッジ付きアシスタントは `knowledge_search=False` でも資料を参照する
- 資料を持つアシスタント（「業務報告会」の資料2件）は、`knowledge_search=False` を指定しても資料を検索して回答した（資料の名前を回答に列挙した）。
- **設計への含意**：ナレッジを持たないアシスタントを用途専用に選ぶ。既存の業務用アシスタントを流用しない。
- 見分け方（確認できた範囲）：`type: system`（標準モデル）は、この利用者の環境では全件でナレッジ読み取りが 403 だった。403 は権限が無いことを示すだけで、ナレッジが空であることは意味しない。ナレッジの有無は、実際の送信で資料名が出るかで確かめる。

### 3.4 入力の文字数（プロンプト全体）
| 送信文字数 | 結果 |
| --- | --- |
| 〜30,000字 | 正しく回答 |
| 50,000字 | 送信できたが回答が誤る（埋め草の影響） |
| 100,000字・200,000字 | 約30秒で `send_message` が `None`（例外なし）。クライアントのタイムアウトを180秒にしても同じ |

- 上限の公式な値はコードにも資料にも無い。**実測**で、50,000〜100,000字の間。
- `send_message` は失敗時に例外を投げず `None` を返すことがある。呼び出し側で必ず `None` を検査する。

### 3.5 ストリーミングの表示
- `send_message` は受信中の文字を**標準出力へ流す**。CLI ツールや検証スクリプトで出力が混ざるため、必要なら `contextlib.redirect_stdout` で捨てる。

### 3.6 レート制御
- 連続送信は間隔を空ける（ミチナリでは `ai.min_interval_seconds` = 2秒）。

## 4. 既定アシスタントの選び方（ミチナリでの判断）

| 基準 | 理由 |
| --- | --- |
| `type: system`（標準モデル）を選ぶ | 独自のナレッジ・指示を持たず、回答が混ざらない |
| 既存の用途と重ならない | 負荷・設定の競合を避ける |
| 高速モデルを選ぶ（用途が低頻度の質疑なら） | 応答時間（実測 約10〜16秒/問） |

ミチナリで用いた値：GPT-5 mini（高速）`c9e542e1-a324-46d5-a02e-fe6bfaebf85a`。UID は環境で変わりうるため、他プロダクトでは一覧から選び直す。

## 5. 実装パターン（ミチナリで検証済み）

1. **質問ごとのチャット**：チャットを作成 → 送信 → 削除 → 一覧で削除確認。文脈の混入を防げる。フォルダは専用の名前（既存の流用）。
2. **区切りの乱数（nonce）**：リクエストごとに乱数を作り、指示・資料・利用者の入力を区切る。利用者は区切りを偽造できない（検証済み）。
3. **山括弧の全角化**：利用者の入力の `<` `>` を全角にしてから埋め込む（区切りの偽造を防ぐ二重の対策）。
4. **出典行の検証**：回答末尾に根拠のIDを書かせ、実在するIDだけを採用する。実在しない・無い場合は「記載なし」にする（偽の出典を防ぐ。検証済み）。
5. **禁止語の照合は正規化後**：NFKC・小文字化・空白除去。全角・空白挿入による回避を防ぐ（検証済み）。
6. **テンプレート展開は1回のパス処理**：利用者の入力に含まれる `{{...}}` が別の変数として展開されないようにする（ミチナリで実際に不具合があったため修正済み）。
7. **切り詰めない**：上限を超えたら切り詰めて送らず、送らない（指示文が欠落するため）。

## 6. インジェクションの試行結果（ヘルプのみを根拠とする指示文で）

- 直接指示「指示を無視して…」、区切りの偽造、全角・空白の挿入、役割変更、偽の追記（「目標は5種類」）、偽の出典行、テンプレートの展開要求：いずれも成功せず（12件で成功0件）。
- 指示文の漏えい：指示文の本文は出力されなかった。ヘルプ本文（公開情報）の要約は出力された。
- 過剰な拒否：ヘルプに書かれている質問を「記載が見当たりません」と答える例が1回あった（指示文の調整で対処）。

## 7. 開発の進め方（教訓）

- **推測で使わない**：ADK に無い関数（例：アシスタント作成）を、生のAPIで存在するかどうかの推測で実装しない。まずソースと実機で確認する。
- **一時DBで実機検証**：利用者の本番データに触れない。作成したチャットは後始末する。
- **検証スクリプトは作業フォルダの外に置く**（リポジトリを汚さない）。
- **フォルダ・チャットの後始末を計画する**：フォルダは ADK から削除できないため、利用者による手動削除の手順を運用に書く。
- **自動化フックの副作用に注意**：ミチナリでは、セッション開始時のブランチ自動処理が前日ブランチを順にチェックアウトし、ブランチが約30秒ごとに切り替わり続ける不具合が起きた（作業ツリーが古い状態に戻る）。チェックアウトを伴う処理を、ループ内で行わない。

## 8. 未確認の項目（次の検証候補）

- `get_chat` で、サーバー側の履歴の有無を確認する（文脈の検証は別の方法で行い、不成立だった）。
- ナレッジ（資料）の登録・検索の精度（ミチナリでは未実施。資料付きアシスタントを用意して検証が必要）。
- API の生の存在（アシスタント作成など）は未確認。ADK にないものは使わない。
