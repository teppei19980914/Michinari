## 2層構成の理由

Releases 一覧ページは各リリースの本文を全文レンダリングするため、本文が長いと配布zip
（Assets）が画面下へ埋もれ、利用者が目的のバージョンを見つけられなくなる。そこで
**Release 本文には要約のみを置き、全変更点はこのディレクトリのファイルに置く**。

| 層 | 置き場所 | 分量の目安 | 役割 |
| --- | --- | --- | --- |
| 要約 | GitHub Release 本文 | 15行以内 | 一覧でのスキャンとダウンロード導線 |
| 詳細 | `docs/release-notes/v{version}.md` | 制限なし | 全変更点・不具合修正・開発者向け補足 |

## 新しいバージョンを追加する手順

1. `docs/release-notes/v{version}.md` を作成し、全変更点を書く
2. ファイル冒頭の水平線より前に、要約ブロックを次のマーカーで囲んで置く

   ```markdown
   <!-- summary:start -->
   （ここに要約。15行以内。破壊的変更・移行時の注意は必ずここに残す）
   <!-- summary:end -->
   ```

3. このファイルの表へ1行追加する
4. `backend/scripts/publish_release.py` を実行する。要約ブロックを抽出し、ダウンロード
   導線と詳細ノートへのリンクを付けた本文を `gh release create --notes-file` へ渡す

要約に必ず残すもの: このバージョンで何ができるようになったかの1〜2文、主な変更の箇条書き
3〜6項目、**破壊的変更と移行時の注意**。不具合修正の一覧・開発者向け補足は詳細側へ置く。

公開のタイミングと注意点は [OPERATIONS.md](../OPERATIONS.md) 7.4 を参照。
