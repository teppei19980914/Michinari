# Michinari v1.2.1 リリースノート

公開日: 2026-09-12
前バージョン: v1.2.0（2026-09-11 公開）

不具合の修正が中心のアップデートです。**読書・仕事の目標を操作したときに、資格試験向けの説明文が出てしまう問題をまとめて直しました。**

**主な変更**
- 読書の目標をクローズすると「受験結果が未登録の科目があります」と表示され、確認を2回求められる問題を修正（確認は1回に）
- 目標の完全削除の確認画面で、読書・仕事の目標にも「科目・教材が削除されます」と誤った説明が出ていた問題を修正
- リソース配分が未設定のときに「エラーが発生しました」としか表示されなかった問題を修正
- リソース配分の超過エラーが「100%を超えています」と古い説明のままだった問題を修正
- クローズ済みの目標を操作したとき、本当のエラーが表示されない問題を修正

データの移行や事前の準備は不要です。これまでに入力した内容はそのまま引き継がれます。

## このバージョンの概要

ミチナリには「資格試験」「読書」「仕事」の3種類の目標があります。v1.2.1 では、**読書・仕事の目標を操作したときに、資格試験向けの説明文がそのまま表示されてしまう問題**をまとめて修正しました。

画面の見た目や操作手順が変わるわけではありません。「表示される説明が、いま操作している目標の種類に合ったものになる」という修正です。

| | v1.2.0 | v1.2.1 |
| --- | --- | --- |
| 読書の目標をクローズするときの確認 | 2回（2回目に資格試験の説明文） | **1回（読書に合った説明文）** |
| 完全削除の確認画面の説明 | すべて「科目・教材が削除されます」 | **目標の種類ごとの説明** |
| リソース配分が未設定のときの案内 | 「エラーが発生しました」 | **何をすればよいかの案内** |
| リソース配分の超過の説明 | 「100%を超えています」 | **時間（分）での説明** |

## 1. 読書の目標のクローズ：確認が1回になり、説明文が正しくなりました

### これまで（v1.2.0）

読書の目標で「クローズする」を押すと、次のようになっていました。

1. 「クローズすると読み取り専用になります。よろしいですか？」→ 確定を押す
2. **「受験結果が未登録の科目があります。結果なしでクローズしますか？」** と表示される
3. もう一度 確定を押すと、ようやくクローズされる

読書の目標には「科目」も「受験結果」もありません。存在しないものについて警告が出るうえ、確認を2回求められていました。

### v1.2.1 から

確認は **1回だけ** になり、説明文も読書に合ったものになります。

> この目標を中断としてクローズします。読み取り専用になり、元に戻すことはできません。読み終えた場合は、書籍タブの「読了として記録する」から記録してください。

### 大切なポイント：「クローズする」と「読了として記録する」は別の操作です

この修正であわせて分かりやすくしたのが、**2つの終わり方の違い**です。

| 操作 | 場所 | 意味 |
| --- | --- | --- |
| **読了として記録する** | 「書籍」タブ | 読み終えた。**読了レポートが作られます** |
| **クローズする** | 画面右上 | 途中でやめた（中断）。レポートは作られません |

これまでは、読み終えたつもりで「クローズする」を押すと、**中断として記録され、読了レポートが作られないまま元に戻せなくなる**おそれがありました。v1.2.1 では確認画面でその違いをはっきり案内します。

## 2. 目標の完全削除：何が消えるのかが正しく表示されるようになりました

アーカイブした目標を「完全に削除」するときの確認画面が、目標の種類にかかわらず資格試験向けの説明になっていました。

### これまで（v1.2.0）

読書の目標でも仕事の目標でも、次のように表示されていました。

- 「この操作は取り消せません。関連する**科目・教材**もすべて削除されます。」
- 「**学習実績**も含めて完全に削除する」
- 「チェックを外すと、実績が1件でも残る**教材**がある場合は削除できません。」

読書の目標に科目や教材はありません。**取り消せない操作なのに、何が消えるのかが正しく伝わっていませんでした。**

### v1.2.1 から

目標の種類に応じた説明に変わります。

| 目標の種類 | 削除されるもの |
| --- | --- |
| 資格試験 | 科目・教材（学習実績） |
| 読書 | 書籍（想起記録） |
| 仕事 | 案件情報（業務記録） |

## 3. リソース配分のエラー案内が正しくなりました

### 配分が未設定のとき

資格試験の目標を開始・再開しようとして、リソース配分が未設定だった場合、これまでは **「エラーが発生しました」** としか表示されず、何をすればよいか分かりませんでした。

v1.2.1 からは **「「リソース配分」タブで配分する時間を設定してください」** と表示されます。

> 補足：v1.1.0 でリソース配分の単位が「割合（％）」から「時間（分）」に変わった際、この案内文だけが対応から漏れていました。

### 配分が多すぎるとき

配分の合計が時間枠の確保時間を超えたときのエラーが、**「リソース配分の合計が100%を超えています」** という古い説明のままでした。現在は割合ではなく時間で配分するため、実態と合っていませんでした。

v1.2.1 からは **「時間枠に配分した時間の合計が、その時間枠の確保時間を超えています」** と表示されます。

## 4. クローズ済みの目標を操作したときに、本当のエラーが表示されるようになりました

複数のタブで同じ目標を開いていた場合など、**すでにクローズされた目標をもう一度クローズしようとする**ことがあります。

これまでは、このとき「受験結果が未登録の科目があります」という無関係な確認文が表示され、確定を押しても同じ画面が出続けるだけで、**本当の原因（すでにクローズ済みであること）が最後まで分かりませんでした。**

v1.2.1 からは「現在の状態では実行できません」と正しく表示されます。

---

## 5. クローズの確認を取り消したあとの動作を修正しました

資格試験の目標で、クローズの確認画面を **キャンセル** したあと、もう一度「クローズする」を開くと、**最初から「結果なしでクローズしますか？」の状態で表示され、確定を1回押すだけでクローズが確定してしまう**問題がありました。

v1.2.1 では、キャンセルすると確認の状態がリセットされ、最初からやり直せます。

## 開発者向けの補足

利用者の操作には影響しませんが、品質を保つための仕組みを整えました。

### 不具合の再発を防ぐ仕組み

- **エラーコードの分離**: 「確認さえ取れば実行できる状態」と「本当に実行できない状態」を同じエラーコード（`INVALID_STATE_TRANSITION`）で返していたことが、上記4の原因でした。`CLOSE_CONFIRMATION_REQUIRED`（409）を新設して区別しています
- **画面のテスト基盤を導入**: `jsdom` + `@testing-library/react` を追加し、確認モーダルの表示・送信内容を自動テストできるようにしました
- **テストの拡充**: バックエンド 1046 件、フロントエンド 234 件。いずれもカバレッジ 100%（行・分岐・関数・文）を閾値として強制しています
- **文言の登録漏れを機械的に検知**: バックエンドが返す全エラーコードに画面文言が存在することを、テストで突き合わせるようにしました（上記3の「案内文の漏れ」を二度と起こさないため）
- **目標種別ごとの分岐を型で保証**: 種別ごとに文言・画面を切り替えている箇所を対応表方式に統一し、種別を追加した際の記述漏れを型チェックが検出するようにしました

### 開発環境の整備

- **`npm install` が失敗する問題を修正**: `openapi-typescript` と TypeScript 6 の依存関係の衝突により、クリーンな環境でセットアップできない状態でした（`frontend/.npmrc`）
- **依存パッケージの脆弱性を解消**: `js-yaml` を 4.3.2 へ更新（GHSA-2883-xcg3-v3hh）。`npm audit` は 0 件です
- **依存脆弱性スキャンの導入**: `osv-scanner` を仮想環境（`myvenv`）配下に導入する手順をルール化しました。アプリ本体（`backend` / `frontend`）の検出は 0 件です

### リリース運用

- リリースノートを「GitHub Releases の要約」と「詳細ノート」の2層構成にしました
- 配布パッケージのタグが、ビルド元のコミットに正しく付くよう修正しました（`publish_release.py --target`）

### 既知の制限

- 画面（コンポーネント）の自動テストは、今回変更した3ファイルのみが対象です（全 74 ファイル中）
- テストの自動実行・リリース判定は未整備です。現時点では手動での実行が必要です
