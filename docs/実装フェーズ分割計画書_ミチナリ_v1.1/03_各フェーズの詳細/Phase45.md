### Phase 45：週次要約の遡りを目標開始日まで広げる（S05）

| 項目 | 内容 |
| --- | --- |
| 目的 | 週次要約の起動時遡及生成（`weekly_summary_service.run_retroactive_generation`）が、固定の検索窓（旧`summary.lookback_weeks`、既定4週）を超えてアプリを起動しなかった期間の週をその後も永久に要約しない不具合（G3）を解消する。遡及対象を全目標中最も早い実質開始日（読書はbook.start_date）の週まで広げ、代わりに1回の起動で生成する件数の上限（新設`summary.retroactive_max_per_run`）で起動の長時間化を抑える |
| 投入文書 | 開発Todo「S05 要約の遡り」v1.0、設計書 ロジック・プロンプト編 15章・24章（L-13）、設計書 データ構造編 5.2、CODING_RULES.md |
| 完了条件 | 開発Todoの作業手順（§3）が全てチェック済みであること。バックエンドのテストが通り、カバレッジが例外処理を除き100%であること |
| 前提の確定 | 生成順序は新しい週から（日次報告への効果が大きいため）。`summary.lookback_weeks`は意味を変えて再利用せず廃止し、新設の`summary.retroactive_max_per_run`（既定10）に置き換える。既存DBに残る`summary.lookback_weeks`の値は無害な孤立データとして残し、削除マイグレーションは行わない。失敗した週の可視化（ログ以外での検知手段）は今回は対象外とする |
