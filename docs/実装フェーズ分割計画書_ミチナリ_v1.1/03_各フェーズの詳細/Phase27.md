### Phase 27：リソース配分スロット単位化の設計文書反映

| 項目 | 内容 |
| --- | --- |
| 目的 | リソース配分を比率（%）からスロット単位の時間（分）へ変更する設計を5文書へ反映し、Phase 28以降が設計書のみを参照して実装できる状態にする |
| 位置づけ | Phase 1〜26とは独立した追加スコープ。既存フェーズの番号・完了条件は変更しない |
| 投入文書 | CLAUDE.md、運用設計ルール、本フェーズ自体 |

**設計確定内容（反映元）**

- リソース配分の入力単位を「目標に対する比率（0〜100%）」から「**時間スロットごとの配分時間（分）**」へ変更する。`goal.resource_ratio` を廃止し `goal_slot_allocation(goal_id, slot_id, minutes)` を新設する
- 上限制約はスロット単位とする（`Σ配分分数 ≤ そのスロットの連続時間`）。比率方式では表現できなかった「どの形の時間をどの目標へ割り当てるか」を利用者が明示できるようにする
- 時間スロットの入力は開始時刻・終了時刻のまま変更しない。算出の正準単位を分（整数）とし、時間（hour）表示は小数第2位以下を切り捨てる（四捨五入しない）
- 日次報告の実績入力を、教材ごとの「投下時間（分）」単独欄から「**配分済みスロットごとの入力欄＋合計の自動算出**」へ変更する。初期値は9.2の按分結果、変更はその日限りでマスタを更新しない、未配分スロットも追加入力できる
- `study_log.minutes_spent` は「スロット別工数の合計」として**存続**させ、内訳を `study_log_slot_time` に持つ。実効速度（8.1）・週次集計・ナレッジエクスポートを無改修で維持するための設計判断である。内訳を持たず按分で推定する案は、実効速度と必要速度が配分という同じ分母を共有して循環参照となり、強制リプラン判定（11.2）が機能しなくなるため採らない
- 読書目標をリソース配分の対象に**含める**。配分の要否を決める軸を「管理型か記録・活用型か」から「**自由な時間に行う活動か否か**」へ改めたことによる（要件定義書6.10）。読書の配分は任意とし、未設定でも進行中へ遷移できる。記録した時間は速度算出に用いず集計・表示・AI文脈にのみ用いる
- 仕事目標は引き続き配分の対象外とする（自由な時間に行う活動ではないため。R-74）
- スロットの短縮・削除により既存の配分が超過する状態は、保存を拒否せず警告する（NT-09を新設）。`study_log_slot_time.slot_id` は `ON DELETE SET NULL` とし、スロットを削除しても実績の合計を失わない
- インポート／エクスポートは旧版との互換を考慮せず、両スキーマ版数を "1.0" → "1.1" へ更新する（利用者が本人のみであり移行の必要がないため）
