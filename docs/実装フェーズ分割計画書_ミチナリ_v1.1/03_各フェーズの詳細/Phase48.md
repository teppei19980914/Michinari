### Phase 48：節目のお祝い

| 項目 | 内容 |
| --- | --- |
| 目的 | 毎日のAIフィードバックは決まった形で返ってくるため、慣れると嬉しさが薄れる。また、AIを設定していない利用者には、続けたくなるご褒美がほとんど無い。記録が節目（連続/累計記録日数・読書の累計ページ数/読了冊数・資格の教材1周完了/全体進捗率・仕事の記録件数/評価期間完走）に届いたときに、キャラクターと一緒にお祝いする演出を追加し、AIがなくても完結する続ける楽しさを足す |
| 投入文書 | 開発Todo「節目のお祝い」v1.0、要件定義書6.18（R-132〜R-137）、仕様書6.5・6.8・6.11、設計書 ロジック・プロンプト編26章、設計書 データ構造編5.2・5.4・6.2、CODING_RULES.md |
| 完了条件 | 開発Todoの作業手順（§3）が全てチェック済みであること。バックエンド・フロントエンドのテストが通り、カバレッジが例外処理を除き100%であること |
| 前提の確定 | 連続/累計記録日数は3種別共通で既存の統計サマリ（`metrics_service.compute_consecutive_report_days`）の定義をそのまま使う（独自の定義は作らない）。節目の履行履歴は新規テーブル`goal_milestone_achievement`（出来事の記録、CLAUDE.mdの現在値保存禁止の対象外）に保存し、閾値は`app_setting`（カンマ区切りの整数文字列）に外部化する。到達判定・永続化は記録確定（finalize系POST）の副作用として行い、GETには副作用を持たせない。既存利用者の更新直後に過去の節目が大量表示されないよう、起動時に一度だけ導入時点までの到達済み節目をお祝い済みとして一括記録する（一度きりフラグで以後は実行しない）。表示はモーダル（既存のアイコン＋CSS紙吹雪アニメーション、`prefers-reduced-motion`で分岐）とし、新規イラストは追加しない。AIは使用しない。節目の一覧は分析画面に新規タブとして追加する（ダッシュボードの2秒要件を避けるため）。読書の累計ページ数・読了冊数は利用者の読書全体（lifetime集計）を対象とし、到達を検知した目標に紐付ける簡略化を採る |
