### Phase 13：読書機能の設計文書反映

| 項目 | 内容 |
| --- | --- |
| 目的 | 確定した読書機能の設計を要件定義書・仕様書・設計書に反映し、Phase 14以降が設計書のみを参照して実装できる状態にする |
| 位置づけ | Phase 1〜12（資格試験機能）とは独立した追加スコープ。既存フェーズの番号・完了条件・既存文書の資格試験関連の記載は一切変更しない |
| 投入文書 | CLAUDE.md、運用設計ルール、本フェーズ自体（設計確定内容の書き起こしが実装対象） |

**設計確定内容（反映元）**

- `goal.category`（GoalCategory: EXAM / READING）を追加し、目標種別を区別する
- `book`（書籍。goal_idにUNIQUE制約＝1目標1冊）、`reading_log`（読書記録。daily_record_id×book_idでUNIQUE）を新設する
- 読書目標のライフサイクルは既存の `goal.status`（DRAFT/ACTIVE/PAUSED/CLOSED）をそのまま流用し、`book` 側に独自のstatus/completed_atは持たせない
- AI連携は「日次報告フィードバック」「読了レポート」の2段構成とし、週次要約は対象外とする。`AiPurpose` に `DAILY_FEEDBACK_READING` / `GOAL_RETROSPECTIVE_READING` を追加し、それぞれ `prompt_template` に新規行、`ai.assistant_uid.*` に新規設定キーを追加する（既存の資格試験用プロンプト・アシスタント設定は無改変）
- 読了レポートは既存の `goal_retrospective`（本文・再生成可・匿名化版保持）をそのまま流用する
- ナレッジエクスポート機能はコード変更なしで流用する（読書目標も既存の対象目標選択肢に含まれることを仕様書に明記するのみ）
- `GET /goals/{id}/plan` は category=READING のとき、日次ノルマ・実効速度ではなく残日数・直近記録日・連続記録日数（・total_pages設定時はページ進捗）を返す軽量な応答に分岐する
- 読書目標は `resource_ratio` のリソース配分プールの対象外とする（前掲の確認事項。異なる場合はここで修正する）
