### Phase 49：復習クイズ

| 項目 | 内容 |
| --- | --- |
| 目的 | 資格試験・読書のテーマ累積（振り返り）は、記録しても読み返すしか使い道が無い。AI（NewtonX）がテーマからクイズを作り、間隔を空けて出題することで、「書いて終わり」から「後で記憶を助けてくれるもの」へ変え、続ける理由を強くする |
| 投入文書 | 開発Todo「復習クイズ」v1.0、要件定義書6.15（想定）、仕様書6.1.3・6.1・6.5・8章、設計書 ロジック・プロンプト編17章、設計書 データ構造編5.6、CODING_RULES.md |
| 完了条件 | 開発Todoの作業手順（§3）が全てチェック済みであること。バックエンド・フロントエンドのテストが通り、カバレッジが例外処理を除き100%であること |
| 前提の確定 | 対象は資格試験・読書（`GoalCategory.EXAM`／`READING`）のテーマ累積（`RecapTheme`）のみ。仕事は対象外。クイズは新規2テーブル（`quiz_question`・`quiz_answer_log`）で管理し、生成はテーマ単位バッチ（起動時、未生成テーマのみ）と利用者操作（作り直す）の両方で行う。出典（報告日付）はそのバッチで実際にAIへ渡した日付集合との照合で検証し、通らない問題は個別に破棄する（出典検証の考え方は目標相談チャットの日付検証方式を参考に新規実装、関数は共有しない）。間隔（既定1・3・7・14・30日）・1テーマあたりの問題数・1日の出題上限は`app_setting`に外部化する。テーマの改名・統合・再構築時は未出題のクイズを削除し作り直す対象とするが、回答履歴（分析用）は削除しない。ダッシュボード初期表示・AI呼び出し失敗時はいずれも既存機能に影響しない（DB読み取りのみ、例外は目標単位で握り潰す）。既存アシスタント（週次要約用）・既存の頻度制御・文字数予算を流用し、新規のAI設定項目は増やさない |
