### Phase 44：日次報告の共通化・全期間化・縮退順の見直し（S04）

| 項目 | 内容 |
| --- | --- |
| 目的 | 資格試験・読書・仕事の日次報告フィードバックが送る「過去の記録」の組み立てを共通化し、目標開始日（読書はbook.start_date）〜対象日の前日の全期間を対象とする（件数・週数の上限を撤廃）。縮退順を「最も古い過去の記録から」に揃え、当日の入力（実績・日記・対話）は縮退の対象外とし、使い切ってもなお上限を超える場合は切り詰めずに送信を中止する |
| 投入文書 | 開発Todo「S04 日次報告の共通化・全期間化・縮退順の見直し」v1.0、設計書 ロジック・プロンプト編 16.5・17.2・17.6・17.8・21.4・22.4・24章（L-12）、仕様書 8.4・8.5・6.11、CODING_RULES.md |
| 完了条件 | 開発Todoの作業手順（§3）が全てチェック済みであること。バックエンド・フロントエンドのテストが通り、カバレッジが例外処理を除き100%であること。既存DBへのマイグレーション（`DAILY_FEEDBACK`テンプレートへの`{{recent_logs}}`追加）が確認できること |
| 前提の確定 | 対話は「当日の入力」として縮退の対象外とする（資格試験の対話履歴トリミング・日記先頭切り詰め、読書・仕事の対話履歴トリミングは廃止）。「切り詰めず送信しない」の適用範囲は日次報告3用途のみとし、総括レポート・読了レポート・月次報告・半期評価・AI評価レポートの5用途（共有エンジン`build_with_degradable_entries`の既存フォールバック仕様）は対象外とする。`summary.inject_weeks`・`ai.reading_recall_recent_days`・`ai.work_recent_log_days`の3設定キーは削除する |
| 同時に修正した既存の不具合 | `reading_feedback_service.py`の`period_start`が`goal.start_date`を参照していた誤りを`book.start_date`へ修正（`book.start_date`は`update_book`で目標開始日と独立に変更できるため、読了レポート（`retrospective_service.py`）との不整合があった） |
