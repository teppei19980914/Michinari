## 1. 本文書の目的

本文書は、ミチナリが提供する機能の全体像、画面構成、および各機能の入出力を定義する。

要件定義書に記載した要求（R-01〜R-60）に対する実現手段を機能単位で示す。データ構造および算出ロジックの詳細は設計書に記載し、本文書では扱わない。

---

## 2. システム概要

### 2.1 システム構成（第1フェーズ）

| 層 | 構成 |
| --- | --- |
| クライアント | ブラウザ上で動作するシングルページアプリケーション |
| サーバ | ローカルホストで動作するAPIサーバ |
| データストア | ローカルファイルベースのリレーショナルデータベース |
| AI連携 | APIサーバと同一プロセス内でAI基盤の開発キットを呼び出す |

利用者はローカルホストのURLにブラウザからアクセスする。外部への通信はAI基盤への呼び出しのみとする。

**ポートに関する制約**

AI基盤の開発キットは、認証フローのフォールバック経路（PAT未設定時のブラウザ認証）でローカルの8400番ポートを使用する設定を既定に持つ。主経路のPAT認証ではこのポートは使用されないが、フォールバック経路を確実に動作させるため、アプリケーションサーバは引き続き8400番以外で起動する。既定値は8100とする。

### 2.2 利用形態

単一利用者による使用を前提とする。認証機構は設けない。

## 5. 画面遷移

### 5.1 全体構造

```
グローバルナビゲーション
  ├─ ダッシュボード（SC-01）※起動時の初期表示
  ├─ 目標一覧（SC-02）
  ├─ カレンダー（SC-05）
  ├─ 分析（SC-09）
  ├─ 設定（SC-11）
  └─ ヘルプ（SC-14）
```

## 6. 画面仕様

### 6.1 SC-01 ダッシュボード

**表示要素**

| 領域 | 内容 |
| --- | --- |
| 今日の一言 | AIが生成した肯定的な短文。生成日が当日でない場合のみ再生成。複数目標が同時進行している場合は目標ごとに独立して生成・表示する（未決事項L-04） |
| 警告バナー | 警告または強制リプラン条件を満たす目標がある場合に表示 |
| 本日のノルマ | 進行中の全教材について、目標分量・目標時間・使用予定スロット・現在周回を一覧 |
| 目標カード | 進行中の各目標について、全体進捗率、残日数、完了予測日との乖離を表示 |
| 統計サマリ | 連続報告日数、直近30日の報告率、バッファ消費率、実効速度 |
| 本日の状態 | 未入力・進捗のみ登録済・報告済のいずれかを表示 |

**操作**

- 本日の報告ボタン。本日の状態に応じて遷移先を切り替える
- 各カードから対応する詳細画面への遷移

**特記事項**

日種別がバッファ日の場合、本日のノルマ領域には「本日はバッファ日です」と表示し、目標分量を0として扱う。ただし実績登録は可能である旨を併記する。

複数目標が同時進行しており本日のノルマに2目標以上の教材が含まれる場合、目標名の見出しで教材をグルーピング表示する（1目標のみの場合は見出しを表示しない）。

「本日」の判定には、設定された1日の境界時刻を用いる。境界時刻が午前4時であれば、午前3時のアクセスは前日として扱う。

### 6.2 SC-03 目標詳細・編集

**目標種別の選択**

目標作成時（GOL-15）に種別（資格試験／読書）を選択する。種別は作成後の変更を許容しない（種別変更は目標の作り直しとする）。以下のタブ構成・入力項目は種別が「資格試験」の場合のものである。種別が「読書」の場合の構成は本節末尾「読書目標（category=READING）の場合」を参照。

**タブ構成（資格試験）**

| タブ | 内容 |

| 教材 | 教材の追加・編集。科目との紐付け。周回進行状況の表示 |
| リソース配分 | 本目標への配分比率の設定 |

**試験科目タブの入力項目**

| 項目 | 型 | 必須 | 備考 |

| 科目名 | 文字列 | 要 | — |
| 受験日タイプ | 選択 | 要 | 期間／確定日 |
| 期間開始日 | 日付 | 条件付 | 受験日タイプが期間の場合 |
| 期間終了日 | 日付 | 条件付 | 受験日タイプが期間の場合 |
| 確定日 | 日付 | 条件付 | 受験日タイプが確定日の場合 |

| 合格点 | 数値 | 任意 | 百分率入力時は0〜100。点数入力時は0〜満点 |
| 満点 | 数値 | 条件付 | 合格点の入力方式が点数の場合のみ、0より大きい値 |

**教材タブの入力項目**

| 項目 | 型 | 必須 | 備考 |
| --- | --- | --- | --- |
| 教材名 | 文字列 | 要 | — |

| 開始日 | 日付 | 要 | — |
| 締切 | 日付 | 要 | 既定値は紐付く科目の最早受験日の前日。上書き可 |
| 必要連続時間 | 数値（分） | 任意 | 未設定時は制約なし |
| 必要環境 | 選択 | 任意 | 制約なし／机上のみ／移動中でも可 |

| 項目 | 内容 |
| --- | --- |
| 総作業量 | 総量 × 予定周回数 |
| 現在周回 | 累積完了量から導出した現在の周回 |

**検証**

- リソース配分の合計が100%を超える場合、保存を拒否する
- 教材の必要連続時間・必要環境を満たすスロットが存在しない場合、警告を表示する。保存は許容する
- 受験日が期間の場合、期間開始日が本日より過去である場合に警告を表示する
- 予定周回数を減らす際、既に完了した周回数を下回る値は拒否する

**状態による制御**

目標の状態がクローズの場合、全項目を読み取り専用とする。

**読書目標（category=READING）の場合**

タブ構成を以下に簡略化する。試験科目・教材・リソース配分・負荷プロファイルの各タブは表示しない（GOL-15、R-64、R-69〜R-71）。

| タブ | 内容 |
| --- | --- |
| 基本情報 | 目標名（書名を既定値とする）、開始日、状態、備考 |
| 書籍 | 書名、著者（任意）、総ページ数（任意）、読了目標日（GOL-16、R-70） |

| 項目 | 型 | 必須 | 備考 |
| --- | --- | --- | --- |
| 書名 | 文字列 | 要 | — |
| 著者 | 文字列 | 任意 | — |
| 総ページ数 | 整数 | 任意 | 未入力の場合、ページ進捗表示を行わない |
| 読了目標日 | 日付 | 要 | — |

基本情報タブ・書籍タブ以外に、読了レポートタブを設ける。内容はSC-13（6.10）参照。

**読了操作**

読書目標には資格試験のSC-10（受験結果登録）に相当する画面を設けない。かわりに書籍タブに「読了として記録する」操作を設け、実行により目標を直接クローズ状態へ遷移させる（確認モーダル表示）。クローズと同時に読了レポートの生成を開始し、ナレッジエクスポート画面（SC-13）へ遷移する（CLS-07、R-67）。中断・断念する場合は、資格試験と共通のGOL-10（目標状態変更）から一時停止・クローズを行う。

目標のクローズ（読了・中断を問わず）以降、全項目を読み取り専用とする（資格試験と同様の状態制御。R-71）。

日次ノルマ・実効速度・完了予測日・警告に関する表示は行わない（R-71）。かわりにGOL-17（読書進捗表示）を基本情報タブに表示する。表示項目は「残日数」「直近記録日」「連続記録日数」とし、総ページ数が入力されている場合のみ「ページ進捗（現在ページ／総ページ数）」を追加表示する。

| スロット名 | 文字列 | 要 | 通勤、始業前など |
| 開始時刻 | 時刻 | 要 | — |

日付が切り替わる時刻を設定する。既定値は午前0時とする。深夜まで学習する習慣がある場合、午前4時などに設定することで、深夜の学習が翌日に計上されることを防ぐ。

**表示要素**

- 曜日別の総確保時間
- 各目標への配分状況と未配分の残量

### 6.5 SC-06 日次報告

**構成**

画面を上下2段に分割する。上段を実績入力、下段をAI対話とする。

**実績入力（上段）**

進行中の全教材について、当日が学習期間内（開始日〜締切）の教材を行として表示する。開始日前の教材は表示しない（先行着手した内容は「本日の行動・所感」に自由記述する）。この絞り込みはSC-01の本日のノルマ・SC-07にも共通で適用される。

複数目標が同時進行しており2目標以上の教材が含まれる場合、SC-01と同様に目標名の見出しで教材をグルーピング表示する（1目標のみの場合は見出しを表示しない）。

| 列 | 内容 |
| --- | --- |
| 教材名 | 表示のみ |
| 現在周回 | 表示のみ。「2周目 / 全3周」の形式 |
| 本日の目標 | 算出された日次ノルマを表示 |
| 投下時間 | 数値入力（分）。進捗のみ登録の場合は任意 |
| 完了分量 | 数値入力 |
| 周回 | 数値入力。既定値は現在の周回数 |
| 品質指標 | 教材の設定方式に応じた入力欄。任意 |

品質指標の入力形式は以下とする。

| 方式 | 入力形式 |
| --- | --- |
| 客観正答率 | 0〜100の数値 |
| 自己採点得点率 | 0〜100の数値 |
| 主観的手応え | 5段階の選択（内部的に20/40/60/80/100へ変換） |

**日記記述（上段下部）**

| 項目 | 内容 |
| --- | --- |
| 本日の行動・所感 | 複数行テキスト。自由記述 |
| 本日学んだこと | 複数行テキスト。当日の学習内容を自らの言葉で記述する欄。プレースホルダに記述例を提示 |

複数目標が同時進行している場合、日記欄は目標ごとに分けて表示する（見出しは2目標以上のときのみ表示。1目標のみの場合は従来通り見出しなし）。対象は当日のノルマ有無に関わらず現在ACTIVEな全目標とし、先行着手した内容を自由記述できる逃げ道を維持する。

**AI対話（下段）**

チャット形式の対話領域とする。初回の応答は、実績入力および日記の内容を確定して送信した時点で生成される。

対話は複数往復可能とする。対話終了後、確定操作により報告が確定する。

**確定処理**

確定により以下が実行される。

1. 実績数値および日記本文を変更不可として保存
2. 対話履歴を保存
3. 当日の記録状態を報告済に変更
4. ダッシュボードへ遷移

確定前に画面を離脱した場合、入力内容は保存されない旨を警告する。

**AI応答が得られない場合**

AI基盤が利用できない場合も、確定操作を許容する。この場合、対話履歴は空となる。

**読書目標の実績入力（REP-13、REP-14）**

進行中の読書目標がある場合、実績入力（上段）に資格試験の教材行とは別枠で書籍ごとの想起欄を表示する。

| 項目 | 内容 |
| --- | --- |
| 書名 | 表示のみ |
| 今日読んだ内容の想起 | 複数行テキスト。必須（R-65）。プレースホルダに「今日はどこまで読みましたか。印象に残ったことは何ですか」等の記述例を提示 |
| 読んだページ数 | 数値入力。任意 |
| 現在ページ | 数値入力。任意。総ページ数が未設定の場合は入力欄を表示しない |

数値実績（読んだページ数・現在ページ）の入力は必須としない（R-65）。想起欄のみの入力でも確定できる。

AI対話（下段）は資格試験と共通のUI構成を用いるが、通信先は別エンドポイント（`POST /records/{date}/reading-chat`）とし、読書用プロンプト（REP-14、17.6参照）で生成する。会話・対話履歴は用途ごとに分離されており（`ai_conversation`の`scope`、および`chat_message.purpose`によるフィルタリング。データ構造編5.4・5.5、ロジック・プロンプト編21.1）、資格試験目標と読書目標が同日に両方進行中でも互いの対話内容は相手のプロンプトに混入しない。

### 6.6 SC-07 進捗のみ登録

## 7. 状態遷移仕様

### 7.1 目標の状態遷移

```
        ┌─────────┐
        │ 下書き  │
        └────┬────┘
             │ 開始
        ┌────▼────┐
   ┌────│ 進行中  │────┐
   │    └────┬────┘    │
   │ 一時停止 │ 受験完了 │ 中断・辞退
   │         │         │
┌──▼──────┐  │  ┌──────▼──────┐
│ 一時停止 │  │  │ クローズ     │
└──┬──────┘  │  │（結果登録なし）│
   │ 復帰     │  └─────────────┘
   └─────────┘
             │
       ┌─────▼──────────┐
       │ クローズ        │
       │（結果登録あり）  │
       └────────────────┘
```

**遷移条件**

| 遷移 | 条件 |
| --- | --- |
| 下書き → 進行中 | 試験科目1件以上、教材1件以上、リソース配分が設定済み |
| 進行中 → 一時停止 | 制約なし。リソース配分を解放する |
| 一時停止 → 進行中 | リソースの空きが元の配分比率以上であること。不足時はエラー |
| 進行中 → クローズ（結果あり） | 全科目の受験結果が登録済み |
| 進行中 → クローズ（結果なし） | 確認モーダルでの承認 |
| クローズ → 他の状態 | 遷移不可 |

クローズへの遷移時、総括レポートの生成を非同期で開始する。生成の成否はクローズ処理の成否に影響しない。

### 7.1.1 アーカイブ状態

アーカイブは `GoalStatus` とは独立したフラグ（`archived_at`）で表現し、状態遷移図には含めない。クローズ後の可視性のみを制御し、`status` 自体は変化しない。

| 遷移 | 条件 |
| --- | --- |
| クローズ済み → アーカイブ | `status` が `CLOSED_WITH_RESULT` または `CLOSED_WITHOUT_RESULT` であること |
| アーカイブ → 復元 | いつでも可能。復元後の `status` はクローズ状態のまま変わらない |
| アーカイブ済み → 完全削除（物理削除） | アーカイブ済みであること。学習実績を含めて削除するか、実績が残る場合は拒否するかを選択する（データ構造編4.2） |

**読書目標（category=READING）の場合の遷移条件**

状態遷移そのもの（下書き／進行中／一時停止／クローズ）は資格試験と共通の`GoalStatus`を用いるが、遷移条件は以下のとおり読み替える。アーカイブ・完全削除の遷移条件（上記7.1.1）は種別を問わず共通であり、完全削除時の実績の道連れ判定は読書目標では想起記録（reading_log）が対象となる（データ構造編4.2）。

| 遷移 | 条件 |
| --- | --- |
| 下書き → 進行中 | 書籍が1件登録済みであること（試験科目・教材・リソース配分は不要） |
| 進行中 → 一時停止 | 制約なし。読書目標は元よりリソース配分を持たないため解放処理は発生しない |
| 一時停止 → 進行中 | 制約なし（リソースの空き確認は行わない） |
| 進行中 → クローズ（`CLOSED_WITH_RESULT`＝読了） | 書籍タブでの「読了として記録する」操作の承認（6.2、`POST /books/{id}/complete`） |
| 進行中 → クローズ（`CLOSED_WITHOUT_RESULT`＝中断） | 確認モーダルでの承認（`POST /goals/{id}/close`。資格試験の「結果なし」クローズと同一エンドポイント） |
| クローズ → 他の状態 | 遷移不可 |

`CLOSED_WITH_RESULT`は資格試験では「合否結果を伴うクローズ」を意味するが、読書では合否が存在しないため「読了という成果を伴うクローズ」という意味に読み替えて用いる（設計書 データ構造編 5.3）。`CLOSED_WITH_RESULT`への遷移時、読了レポートの生成を非同期で開始する。生成の成否はクローズ処理の成否に影響しない（資格試験の総括レポートと同じ方針）。

  ┌────────┐
  │ 未入力 │
  └───┬────┘
      │
      ├──[実績数値のみ入力]──→ ┌──────────────┐
      │                        │ 進捗のみ登録済 │

### 8.2 会話の管理方針

**制約**

開発キットでは、メッセージ送信前に会話を作成し、その識別子を指定する必要がある。会話はAI基盤側に永続化される。

**方針：用途と日付ごとに会話を分離する**

| 用途 | 会話の単位 | 会話のタイトル |
| --- | --- | --- |
| 日次報告 | 1日1会話（複数目標にまたがりうるため目標非依存） | `{日付} 日次報告` |
| 週次要約 | 1週1会話（目標ごと） | `{週開始日}週 週次要約` |
| 今日の一言 | 1日1目標につき1会話（ACTIVEな目標が無い日のみ目標非依存の1件） | `{日付} 今日の一言 {目標名}` |
| 総括レポート | 目標ごと1会話 | `総括レポート` |

**方針の理由**

会話を用途ごとに分離することで、異なる目的のプロンプトが文脈として混入することを防ぐ。日次報告のフィードバックが、朝に生成した「今日の一言」の文脈に引きずられる事態を構造的に排除する。

今日の一言は目標ごとに独立した会話・プロンプト呼び出しとする（未決事項L-04）。複数目標が同時進行している場合に、他目標の情報を一切混ぜないことで、順調な目標に引っ張られて停滞している目標の実態と乖離した一言が生成されることを構造的に防ぐ。

日をまたぐ文脈は、会話の継続によってではなく、週次要約をプロンプトに注入することで実現する。この方式であれば、注入する情報量をアプリケーション側で完全に制御できる。

**フォルダによる整理**

すべての会話をフォルダ配下に作成する。目標に紐づく会話（週次要約・総括レポート・今日の一言）はフォルダ名「`{接頭辞}_{目標名}`」の目標別フォルダに、目標に紐づかない会話（日次報告、およびACTIVEな目標が無い日の今日の一言）は接頭辞そのものを名前とする共通フォルダに配置する。接頭辞は設定から変更可能とする。共通フォルダをAI基盤側で削除するだけで、アプリ由来の会話を一括で解放できる。

**会話識別子の保持**

作成した会話の識別子はローカルに保持する。一覧取得APIを毎回呼び出さない。

### 8.3 メッセージ送信の指定

| パラメータ | 指定値 | 理由 |
| --- | --- | --- |
| Web検索 | 無効 | 既定値が有効のため明示指定が必須。試験対策の文脈に無関係な検索結果が混入することを防ぐ |
| ナレッジ検索 | 無効 | 本アプリはアシスタントのナレッジを使用しない |
| 親メッセージ順序 | 送信するが文脈維持には用いない（8.3.1参照） | 同一日内の複数往復における文脈維持は対話履歴の注入（8.4）で実現する |
| 画像・文書・音声 | 使用しない | MVPの範囲外 |

#### 8.3.1 親メッセージ順序に関する既知の制約（要検証）

導入したAI基盤の開発キット（NewtonX ADK v0.10.5）を実際にソースコードで確認したところ、`send_message()`のメソッドシグネチャに親メッセージ順序を指定する引数が存在せず、送信内容には常に固定値0が設定されることを確認した。バンドルされた公式ドキュメント（APIリファレンス、利用ガイド、トラブルシューティング）はすべてこのパラメータが機能する前提で書かれており、ドキュメントと実装が矛盾している。

**この制約を前提に、本アプリは以下の方針を取る。**

- AI基盤側の会話スレッド機能（親メッセージ順序による文脈継承）には依存しない
- 同一日内の複数往復における文脈維持は、本アプリが独自に保持する対話履歴（`chat_message`）を毎回のプロンプトへ全文注入する方式（8.4「対話履歴」）で実現する。この方式はAI基盤側の実装状況によらず機能する
- `ai_conversation.last_parent_order` の値は将来の開発キット改修に備えて記録は継続するが、現状は文脈維持の実効性を持たない
- 回答が出力上限で途切れた場合の継続取得（開発キット側が推奨する「終端マーカー方式」）も親メッセージ順序に依存するため、本アプリでは代わりに直前の応答本文をプロンプトに含めて「続きを出力してください」と自己完結した指示で送信する方式を取る

この制約は導入したADKのバージョン（v0.10.5）に起因するものであり、将来のバージョンアップで解消される可能性がある。解消された場合は、親メッセージ順序による文脈継承を主とし、対話履歴の全文注入を縮退時のみに用いる構成へ最適化してよい。

**アシスタントへのナレッジ登録は行わない。** アシスタントが組織内で共有される可能性があり、個人の学習記録を登録することは不適切である。

### 8.4 日次報告フィードバック（AI-01）の入力構成

システムが保持する定型プロンプトに対し、以下の情報を差し込む。

| 区分 | 差し込む情報 |
| --- | --- |
| 目標情報 | 試験名、科目構成、各科目の受験日、残日数 |
| 教材情報 | 教材ごとの総量、予定周回、現在周回、完了量、残量、締切、必要連続時間、必要環境 |
| 計画状態 | 日次ノルマ、必要速度、実効速度（周回別）、完了予測日、締切との乖離 |
| 負荷状態 | 当日の日種別、負荷係数、バッファ消費率 |
| 当日実績 | 教材別の投下時間、完了分量、周回、品質指標 |
| 当日記述 | 本日の行動・所感、本日学んだこと |
| 過去傾向 | 直近の週次要約 |
| 対話履歴 | 本日の対話における過去の往復 |

全期間の日記原文は入力に含めない。

**読書日次報告フィードバック（AI-06）の入力構成**

| 区分 | 差し込む情報 |
| --- | --- |
| 書籍情報 | 書名、著者、読了目標日、残日数 |
| 当日の想起 | 今日読んだ内容の想起、読んだページ数、現在ページ（入力があれば） |
| 過去の記録 | 直近`ai.reading_recall_recent_days`（既定14）日分の想起記録（週次要約は用いない。ロジック・プロンプト編15章・21.4参照） |
| 対話履歴 | 本日の対話における過去の往復 |

日次ノルマ・実効速度・完了予測日・締切との乖離など、8.4本文の「計画状態」「負荷状態」に相当する情報は差し込まない（読書は定量的な計画管理の対象外。R-71）。

### 8.5 プロンプトの段階的縮退

**制約**

AI基盤の入力上限は明示されていない。

**方針**

プロンプトを組み立てた後、文字数が設定値を超える場合、以下の順序で情報を削減する。

| 順位 | 削減対象 | 理由 |
| --- | --- | --- |
| 1 | 古い週次要約から順に除外 | 直近ほど関連性が高い |
| 2 | 教材情報の詳細度を下げる | 締切が遠い教材を集約表示にする |
| 3 | 当日の対話履歴を古い往復から除外 | 直近の往復が最も重要 |
| 4 | 日記本文を末尾優先で切り詰める | 完全な除外は避ける |

縮退が発生した場合、その旨を画面上に控えめに表示する。利用者が「なぜ言及されない情報があるのか」を把握できるようにするためである。

### 8.6 応答に対する要求

定型プロンプトは、以下を満たす応答を得るように構成する。

| 要求 | 内容 |
| --- | --- |
| 状況の解釈 | 数値実績と自然言語記述を統合し、進捗の背景要因を推定する |
| 成長の指摘 | 過去の記述との比較により、説明の解像度や構造化の変化を指摘する |
| 行動の提案 | 翌日以降の具体的な行動を提案する |
| 双方向の調整 | 負荷を増やす提案と減らす提案の双方を選択肢として持つ |

**負荷を減らす提案の段階**

| 段階 | 提案内容 |
| --- | --- |
| 軽 | 特定期間の負荷係数の引き下げ |
| 中 | 教材の優先順位変更、学習範囲の絞り込み、予定周回数の削減 |
| 重 | 受験日の後ろ倒し、目標の一時停止 |
| 即時 | 当日の休息 |

### 8.7 認証

**認証方式はPersonal Access Token（PAT）を主とする。** 導入した開発キット（NewtonX ADK）の現行の公式利用ガイドは、Host（サブドメイン）とPATによる認証を標準的な方法として案内しており、ブラウザ経由のOAuth／デバイスコード認証はEntraID構成時のフォールバック経路として内部に残るのみである。当初の設計はブラウザ認証を主経路と想定していたが、公式情報にあわせて以下のとおり改める。

| 項目 | 方針 |
| --- | --- |
| 認証情報の管理 | 開発キットの仕組みに委ねる。独自の資格情報管理を実装しない。Host（例: `xxx.newton-x.net`）とPATは、設定画面（SC-11）から開発キットの設定へ反映する |
| PATの発行 | NewtonXのWeb版アカウント画面で利用者自身が発行する（本アプリからは発行できない）。設定画面に発行手順への案内を表示する |
| 起動時 | Host・PATが設定済みかを確認する。開発キットはPAT設定時、他の認証手段より優先してこれを使用する |
| 未設定・無効時 | 設定画面でHostとPATの入力を促す。フォールバックとしてブラウザ経由の認証フロー（バックグラウンドスレッドで実行）を提供するが、主経路としては使用しない |
| 認証状態の公開 | クライアントには真偽値のみを返す。PAT・トークンは送出しない |
| リダイレクト先（フォールバック時のみ） | 開発キットの既定値（ローカル8400番）を使用する。アプリケーションサーバは別ポート（8100）で起動する |

### 8.8 エラー処理

| エラー種別 | 応答コード | 画面での扱い |
| --- | --- | --- |
| 未認証・トークン期限切れ | AI_AUTH_REQUIRED | 設定画面での再認証を促すメッセージを表示 |
| タイムアウト | AI_TIMEOUT | 再送ボタンを表示。実績入力の内容は保持する |
| 通信エラー・頻度制限 | AI_ERROR | エラー内容を表示。再送ボタンを表示 |
| 会話操作の失敗 | AI_ERROR | 同上 |
| 設定不備 | AI_CONFIG_ERROR | 設定画面への遷移を促す |

**実装上の注意（タイムアウトの判定方法）**

導入した開発キットの例外クラスは `NewtonXError` / `AuthenticationError` / `APIError` / `ConfigurationError` / `FileUploadError` / `ChatError` の6種であり、タイムアウト専用の例外クラスは存在しない。通信タイムアウトも内部的に `APIError` へ一律ラップされるため、型による判定はできない。本アプリでは、呼び出し側で計測した経過時間が設定値（`ai.timeout_seconds`）を超えているか、またはエラーメッセージにタイムアウトを示す文字列が含まれるかによって `AI_TIMEOUT` を判定する。

**重要な制約**

AI呼び出しの失敗により、実績入力の内容が失われてはならない。日次報告画面では、実績と日記の入力内容をクライアント側の状態として保持し、AI応答の成否とは独立させる。

AI応答が得られない状態でも、報告の確定を許容する。AIとの対話は本アプリの中核だが、それが利用できないことを理由に記録自体が失われるのは本末転倒である。

### 8.9 呼び出し頻度の制御

頻度制限が存在する可能性があるため、連続する呼び出しの間隔に下限を設ける。既定値は2秒とする。

週次要約の遡及生成では複数回の呼び出しが連続するため、この制御が特に重要となる。

### 8.9.1 用途別アシスタントの選定（実機確認済み）

連携箇所（8.1）ごとに既定のアシスタントを設定する。全用途を単一アシスタントに固定せず、`get_assistants()`が返す各アシスタントの説明文に基づき、タスク特性に合ったものを既定値とする。

| 連携ID | 用途 | 既定アシスタント | 選定理由 |
| --- | --- | --- | --- |
| AI-01 | 日次報告フィードバック | GPT-5.4（高性能） | 複雑なタスクの整理や具体的な提案に適しており、状況解釈・成長の指摘・行動提案という要求（8.6）に合致する |
| AI-02 | 週次要約生成 | Gemini 2.5 Flash（高速） | 要約に適した特性を持ち、起動時の複数週遡及生成（速度が重要）に適する |
| AI-03 | 今日の一言生成 | GPT-5.4-mini（高速） | 速度と情報整理のバランスに優れ、ダッシュボードでの非同期表示に適する |
| AI-04 | 総括レポート生成 | GPT-5.4（高性能） | AI-01と同様、低頻度・高品質重視のタスクのため同一アシスタントとする |
| AI-06 | 読書日次報告フィードバック | 未定（実環境での疎通確認後に選定） | 想起の言語化を助ける対話であり、負荷は低いためAI-01より高速寄りのアシスタントを想定 |
| AI-07 | 読了レポート生成 | 未定（実環境での疎通確認後に選定） | AI-04と同様、低頻度・高品質重視のタスク |

各アシスタントの識別子は `app_setting`（`ai.assistant_uid.*`、設計書 データ構造編 5.2）に既定値として保持し、設定画面（SC-11）から用途ごとに変更できる（Phase16実装済み）。AI-06・AI-07の既定値は空欄のまま初期投入されており、8.9.1本文の非対応アシスタント一覧を踏まえ、実環境（Phase11相当の疎通確認）で軽量な疎通テストを行った上で選定する。

**既知の非対応アシスタント**：導入済み環境で以下2件は`send_message`が常に失敗することを実機確認済みである。設定画面の選択肢から除外するか、選択・保存時に疎通確認を行うことが望ましい。

| アシスタント名 | 状態 |
| --- | --- |
| GPT-4o mini（高速） | 使用不可（404で確認済み） |
| GPT-4o（高性能） | 使用不可（404で確認済み） |

この一覧は将来変動しうるため、ハードコードした除外リストのみに頼らず、送信失敗時のエラーハンドリング（8.8のAI_ERROR、再送・再選択の導線）で汎用的に吸収できる設計とする。

### 8.10 稼働状況の確認

起動時にAI基盤の利用可否を確認し、設定画面に表示する。利用不可の場合、AI連携機能を無効化し、実績記録のみが可能な状態とする。

| 対象 | 方針 |
| --- | --- |
| 必須項目 | 入力欄単位で即時検証し、未入力を明示する |

| 読書：想起 | 想起本文は必須、読んだページ数・現在ページは0以上の整数とする（任意入力） |
| 読書：冊数 | 1目標に対して書籍を2件以上登録できない |
