## 1. 本文書の目的

本文書は、ミチナリが提供する機能の全体像、画面構成、および各機能の入出力を定義する。

要件定義書に記載した要求（R-01〜R-60）に対する実現手段を機能単位で示す。データ構造および算出ロジックの詳細は設計書に記載し、本文書では扱わない。

---

## 2. システム概要

### 2.1 システム構成（第1フェーズ）

| 層 | 構成 |
| --- | --- |
| クライアント | ブラウザ上で動作するシングルページアプリケーション |
| サーバ | ローカルホストで動作するAPIサーバ |
| データストア | ローカルファイルベースのリレーショナルデータベース |
| AI連携 | APIサーバと同一プロセス内でAI基盤の開発キットを呼び出す |

利用者はローカルホストのURLにブラウザからアクセスする。外部への通信はAI基盤への呼び出しのみとする。

**ポートに関する制約**

AI基盤の開発キットは、認証フローのフォールバック経路（PAT未設定時のブラウザ認証）でローカルの8400番ポートを使用する設定を既定に持つ。主経路のPAT認証ではこのポートは使用されないが、フォールバック経路を確実に動作させるため、アプリケーションサーバは引き続き8400番以外で起動する。既定値は8100とする。

### 2.2 利用形態

単一利用者による使用を前提とする。認証機構は設けない。

## 6. 画面仕様

### 6.1 SC-01 ダッシュボード

**表示要素**

| 領域 | 内容 |
| --- | --- |
| 今日の一言 | AIが生成した肯定的な短文。生成日が当日でない場合のみ再生成。複数目標が同時進行している場合は目標ごとに独立して生成し、目標タブで選択中の1目標分のみ表示する（1.1改14） |
| 警告バナー | 警告または強制リプラン条件を満たす目標がある場合に表示 |
| 本日のノルマ | 進行中の全教材について、目標分量・目標時間・使用予定スロット・現在周回を一覧 |
| 目標カード | 進行中の各目標について、全体進捗率、残日数、完了予測日との乖離を表示 |
| 統計サマリ | 連続報告日数、直近30日の報告率、バッファ消費率（資格試験目標のみ）、実効速度 |
| 本日の状態 | 未入力・進捗のみ登録済・報告済のいずれかを表示 |

**操作**

- 本日の報告ボタン。本日の状態に応じて遷移先を切り替える
- 各カードから対応する詳細画面への遷移
- 着手中（ACTIVE）の目標が2件以上ある場合、画面上部の目標タブ（日次報告6.5と同じGoalTabBar）で対象目標を1件選択して切り替える（1.1改14）。今日の一言・警告バナー・本日のノルマ・目標カード・統計サマリは選択中の目標分のみを表示する。着手中の目標が0〜1件の場合は目標タブを表示せず、従来どおりその目標（または該当なし）の内容をそのまま表示する

**特記事項**

日種別がバッファ日の場合、本日のノルマ領域には「本日はバッファ日です」と表示し、目標分量を0として扱う。ただし実績登録は可能である旨を併記する。

本日の状態（未入力・進捗のみ登録済・報告済）・本日の日種別は、目標に紐づかないアプリ全体の値であるため、目標タブの切り替えの影響を受けない。

統計サマリのうちバッファ消費率は、選択中の目標が資格試験目標（category=EXAM）の場合にのみ表示する（1.1改16）。読書・仕事目標は日種別による計画運用の対象外であり（R-71・R-74）、バッファ（予備日）という概念自体を持たないためである。実効速度も同じ理由で教材を持つ資格試験目標にのみ表示される。

「本日」の判定には、設定された1日の境界時刻を用いる。境界時刻が午前4時であれば、午前3時のアクセスは前日として扱う。

**1.1改14での変更点**：従来は「進行中の全目標を1画面で俯瞰する画面」として、本日のノルマ・目標カード・統計サマリ・今日の一言のいずれも複数目標分を1画面にグルーピング表示していた（1.1改8で日次報告のみ目標タブ化した際、ダッシュボードは対象外と明記していた）。目標ごとに機能を分離する設計（6.5・6.4参照）をダッシュボードにも統一するため、この判断を撤回し、上記の目標タブ方式に変更した。

**今日の一言の対象目標について**：読書目標（category=READING）は今日の一言の対象外とする（6.10参照）。仕事目標（category=WORK）は読書と異なり対象に含める（R-77、DSH-07・GOL-19で算出する経過日数・直近記録日・連続記録日数・直近の月次報告有無を用いて生成する）。したがって今日の一言の対象は「資格試験目標および仕事目標、読書目標のみ除外」となる。

読書目標・仕事目標の残日数・直近記録日・連続記録日数（・書籍のページ進捗）は目標カードに、資格試験目標の全体進捗率・完了予測日との乖離とは異なる表示要素として含める（DSH-06・DSH-07）。

| 必要環境 | 選択 | 任意 | 制約なし／机上のみ／移動中でも可 |
| 品質指標の方式 | 選択 | 要 | 客観正答率／自己採点得点率／主観的手応え／記録しない |

**教材タブの表示項目**

| 項目 | 内容 |
| --- | --- |
| 総作業量 | 総量 × 予定周回数 |
| 現在周回 | 累積完了量から導出した現在の周回 |
| 周回進捗 | 現在周回内の完了率 |
| 全体進捗 | 総作業量に対する完了率 |

**リソース配分タブの入力項目**

SC-04（6.3）で登録済みの時間スロットを1行ずつ表示し、行ごとに本目標への配分時間を入力する（GOL-08、R-84）。

| 項目 | 型 | 必須 | 備考 |
| --- | --- | --- | --- |
| スロット名 | 表示のみ | — | 適用曜日・環境タグ・連続時間を併記する |
| 空き時間 | 表示のみ | — | スロットの連続時間 − 他目標の配分時間の合計 |
| 本目標への配分時間 | 数値（分） | 任意 | 0以上の整数。未入力は0として扱う |

配分時間の合計（週あたりの確保時間）を画面に表示する。時間スロットが1件も登録されていない場合は、SC-04への遷移リンクのみを表示する。

**検証**

- あるスロットについて、進行中の全目標の配分時間の合計がそのスロットの連続時間を超える場合、保存を拒否する（NT-04）
- 教材の必要連続時間・必要環境を満たすスロットが存在しない場合、警告を表示する。保存は許容する
- 受験日が期間の場合、期間開始日が本日より過去である場合に警告を表示する
- 予定周回数を減らす際、既に完了した周回数を下回る値は拒否する

**状態による制御**

目標の状態がクローズの場合、全項目を読み取り専用とする。

**読書目標（category=READING）の場合**

タブ構成を以下に簡略化する。試験科目・教材・負荷プロファイルの各タブは表示しない（GOL-15、R-69〜R-71）。リソース配分タブは、読書も自由な時間に行う活動でありスロットを奪い合うため表示する（R-64、要件定義書6.10）。

| タブ | 内容 |
| --- | --- |
| 基本情報 | 目標名（書名を既定値とする）、開始日、状態、備考 |
| 書籍 | 書名、著者（任意）、総ページ数、読了目標日（GOL-16、R-70） |
| リソース配分 | 時間スロットごとの、本目標への配分時間（分）の設定。入力項目・検証は資格試験と共通 |

読書目標のリソース配分は**任意**とする。未設定（全スロット0分）のままでも進行中へ遷移できる（R-64）。読書は日次ノルマ・完了予測を持たないため、配分が0でも機能が成立するためである。

書籍タブの入力項目は以下のとおり。

| 項目 | 型 | 必須 | 備考 |
| --- | --- | --- | --- |
| 書名 | 文字列 | 要 | — |
| 著者 | 文字列 | 任意 | — |
| 総ページ数 | 整数 | 要 | 1以上。ページ進捗を常に表示できるようにするため必須とする（1.1改16） |
| 読了目標日 | 日付 | 要 | — |

基本情報タブ・書籍タブ以外に、読了レポートタブを設ける。内容はSC-13（6.10）参照。

**読了操作**

読書目標には資格試験のSC-10（受験結果登録）に相当する画面を設けない。かわりに書籍タブに「読了として記録する」操作を設け、実行により目標を直接クローズ状態へ遷移させる（確認モーダル表示）。クローズと同時に読了レポートの生成を開始し、ナレッジエクスポート画面（SC-13）へ遷移する（CLS-07、R-67）。中断・断念する場合は、資格試験と共通のGOL-10（目標状態変更）から一時停止・クローズを行う。

目標のクローズ（読了・中断を問わず）以降、全項目を読み取り専用とする（資格試験と同様の状態制御。R-71）。

日次ノルマ・実効速度・完了予測日・警告に関する表示は行わない（R-71）。かわりにGOL-17（読書進捗表示）を基本情報タブに表示する。表示項目は「残日数」「直近記録日」「連続記録日数」「ページ進捗（現在ページ／総ページ数）」とする。総ページ数は必須のため、現在ページが一度でも入力されていればページ進捗を常に表示する（現在ページが未入力の間のみ非表示）。進捗率は100%を上限とし、これを超えて表示することはない（1.1改16）。

**仕事目標（category=WORK）の場合**

タブ構成を以下に簡略化する。試験科目・教材・リソース配分・負荷プロファイルの各タブは表示しない（GOL-15、R-74、6.11）。

| タブ | 内容 |
| --- | --- |
| 基本情報 | 目標名（案件名を既定値とする）、開始日、状態、備考 |
| 案件情報 | 案件名（取引先・案件の呼称、任意）、想定業務内容、着手日（GOL-18、R-72、R-73） |

案件情報タブの入力項目は以下のとおり。

| 項目 | 型 | 必須 | 備考 |
| --- | --- | --- | --- |
| 取引先・案件の呼称 | 文字列 | 任意 | — |
| 想定業務内容 | 複数行テキスト | 要 | 営業・顧客から事前に伝えられた内容。登録後も更新可能（更新は上書きとし、変更履歴は保持しない。R-73） |
| 着手日 | 日付 | 要 | — |

書籍と異なり読了目標日に相当する項目は持たない（案件には納期未定の場合があり、読書の読了目標日のような必須の外部制約が存在しないため。データ構造編5.3参照）。

基本情報タブ・案件情報タブ以外に、月次報告タブ・半期評価タブを設ける。ナレッジエクスポート機能はSC-13（6.10）参照。月次報告タブ・半期評価タブは以下のとおり（2026-09-04改訂、要件定義書R-78・R-79・R-82・R-83）。

- 「ドラフトを生成」ボタンを持つ。押下時、対象期間（月次報告は前月、半期評価は当該半期が既定値。ロジック・プロンプト編22.5）のドラフトをAIが生成し、そのまま同タブ内にレビュー用フォームとして表示する（生成結果を別画面に遷移させない）
- レビュー用フォームは、当該期間の目標（`target_goal_text`）・業務内容の要約・達成度（1〜5、選択式）・達成状況の振り返り・来月／次半期の目標案・報告連絡事項（月次報告のみ）を、それぞれ編集可能な入力欄として表示する。利用者はAIの生成内容をその場で修正でき、「保存」操作で確定する（保存のたびに内容を上書きする。修正履歴は保持しない。R-82）
- 生成済みの場合は対象期間を選択して過去分を閲覧・編集できる（過去分の編集もレビュー用フォームと同じ画面・同じ操作で行う）
- 前期に相当する行が存在しない場合（案件着手直後等）、当該期間の目標欄のみを利用者が直接入力して保存できる（AI生成を待たずに運用を開始できる。R-83）
- 「Markdownをダウンロード」ボタンを持つ。押下時、現在保存されている内容から組み立てたMarkdown文書（ロジック・プロンプト編22.6のテンプレート）をファイルとしてダウンロードする。生成直後・未保存の内容ではなく、保存済みの内容を対象とする
- ダッシュボードの仕事目標カード（DSH-07）から、対象の仕事目標の月次報告タブへ直接遷移するボタンを設ける（即座にダウンロードは行わない。生成結果をレビューせず社内へ提出する事故を防ぐため）

**クローズ操作**

仕事目標には資格試験のSC-10（受験結果登録）に相当する画面を設けない。案件の終了は、資格試験と共通のGOL-10（目標状態変更）から行う。案件が納品等の成果を伴って終了した場合は「結果あり」（`CLOSED_WITH_RESULT`）、中止・打ち切りの場合は「結果なし」（`CLOSED_WITHOUT_RESULT`）を選択する（いずれも確認モーダル表示）。読書と異なり、クローズ操作は月次報告・半期評価の生成契機ではない（月次報告・半期評価は案件の進行中に周期的に生成する。CLS-09〜CLS-12）。

目標のクローズ以降、全項目を読み取り専用とする（資格試験と同様の状態制御）。

日次ノルマ・実効速度・完了予測日・警告に関する表示は行わない（R-74）。かわりにGOL-19（仕事進捗表示）を基本情報タブに表示する。表示項目は「経過日数」「直近記録日」「連続記録日数」「直近の月次報告有無」とする。

### 6.3 SC-04 リソースマスタ設定

**時間スロットの入力項目**

| 項目 | 型 | 必須 | 備考 |
| --- | --- | --- | --- |
| スロット名 | 文字列 | 要 | 通勤、始業前など |
| 開始時刻 | 時刻 | 要 | — |
| 終了時刻 | 時刻 | 要 | — |
| 環境タグ | 選択 | 要 | 机上のみ／移動中でも可 |
| 適用曜日 | 複数選択 | 要 | 月〜日 |

連続時間は開始・終了時刻から自動算出する（R-85）。利用者に時間量を直接入力させることはしない。

**時間の単位と表示規則**

算出・保持の単位は分（整数）とする。時間（hour）で表示する箇所では、**小数第2位以下を切り捨てて小数第1位まで**を表示する（例：50分＝0.8333…時間 → 「0.8時間」）。切り捨ては表示時にのみ適用し、算出には常に分（整数）の値を用いる。四捨五入は用いない。

**日種別の既定設定**

曜日ごとに計画日またはバッファ日を選択する。祝日については、祝日データに含まれる日を一律でバッファ日とするか否かを選択する。

**1日の境界時刻**

日付が切り替わる時刻を設定する。既定値は午前0時とする。深夜まで学習する習慣がある場合、午前4時などに設定することで、深夜の学習が翌日に計上されることを防ぐ。

**表示要素**

- 曜日別の総確保時間
- スロットごとの、各目標への配分時間と未配分の残り時間
- 環境タグ別の時間内訳

スロットの配分時間の合計がそのスロットの連続時間を超えている場合、当該スロットに超過分を明示した警告を表示する（NT-09）。この状態は、配分の設定後にスロットを短縮・削除した場合に発生する。

### 6.5 SC-06 日次報告

**構成**

画面を上下2段に分割する。上段を実績入力、下段をAI対話とする。

着手中（ACTIVE）の目標が2件以上ある場合、画面上部に目標タブを表示し、対象目標を1件ずつ選択して切り替える（目標設定画面のカテゴリ選択と同様、選択肢は着手中の目標に限る）。実績入力・日記・AI対話は選択中の目標の種別（資格試験／読書／仕事）に応じた内容のみを表示し、他の目標の入力欄は表示しない。ただし下書き値はタブの選択に関わらず全目標分をローカルに保持し続けるため、タブを切り替えても入力内容は失われない。着手中の目標が0〜1件の場合はタブを表示せず、従来通りその目標の内容をそのまま表示する。

確定（finalize）はカテゴリ（資格試験／読書／仕事）ごとに独立している（1.1（改13））。あるカテゴリの確定ボタンを押すと、そのカテゴリの実績・日記のみが確定済み（報告済）となり、そのタブは以降そのセクションのみ読み取り専用表示に切り替わる。他カテゴリの確定状態には影響せず、引き続き入力・確定できる。当日中に着手しているすべてのカテゴリが確定済みになった時点で、初めてダッシュボードへ遷移する。

**実績入力（上段、資格試験目標選択時）**

進行中の教材のうち、当日が学習期間内（開始日〜締切）のものを行として表示する。開始日前の教材は表示しない（先行着手した内容は「本日の行動・所感」に自由記述する）。この絞り込みはSC-01の本日のノルマ・SC-07にも共通で適用される。

上記の目標タブにより、この一覧には選択中の1目標の教材のみが含まれるため、目標名の見出しは表示しない（ダッシュボードSC-01も1.1改14で同じ目標タブ方式に変更されたため、目標名の見出しによるグルーピング表示は行わない）。

| 列 | 内容 |
| --- | --- |
| 教材名 | 表示のみ |
| 現在周回 | 表示のみ。「2周目 / 全3周」の形式 |
| 本日の目標 | 算出された日次ノルマを表示 |
| 時間枠ごとの投下時間 | 後述「時間枠ごとの投下時間の入力」を参照 |
| 投下時間（合計） | 表示のみ。時間枠ごとの入力値の合計を自動算出 |
| 完了分量 | 数値入力 |
| 周回 | 数値入力。既定値は現在の周回数 |
| 品質指標 | 教材の設定方式に応じた入力欄。任意 |

**時間枠ごとの投下時間の入力（R-14、R-86）**

投下時間は教材ごとに1つの欄で入力するのではなく、**教材の行の中に、その目標が配分している時間スロットごとの入力欄を並べて**入力する。教材の投下時間はこれらの合計として自動算出し、実効速度の算出にはこの合計を用いる。

| 項目 | 内容 |
| --- | --- |
| 表示するスロット | 当日の曜日に該当し、かつ選択中の目標がリソース配分を設定しているスロット |
| 初期値 | リソース配分の設定値を、そのスロットに適合する教材へ按分した値（ロジック・プロンプト編9.2） |
| 変更の扱い | 入力値の変更はその日の実績としてのみ保存し、リソース配分の設定値（マスタ）は変更しない |
| 未配分スロットの追加 | 「他の時間枠を追加」操作により、配分していないスロットを行に追加して入力できる。予定外の空き時間に学習した分を記録できないと、投下時間が実態より小さく計上され実効速度が過大に算出されるため |

全スロットの入力欄が空欄の場合、その教材の投下時間は「未入力」として扱う（0分ではない）。未入力の実績は実効速度の算出対象から除外される（ロジック・プロンプト編8.4）。

品質指標の入力形式は以下とする。

| 方式 | 入力形式 |
| --- | --- |
| 客観正答率 | 0〜100の数値 |
| 自己採点得点率 | 0〜100の数値 |
| 主観的手応え | 5段階の選択（内部的に20/40/60/80/100へ変換） |

**日記記述（上段下部、資格試験目標選択時）**

| 項目 | 内容 |
| --- | --- |
| 本日の行動・所感 | 複数行テキスト。自由記述 |
| 本日学んだこと | 複数行テキスト。当日の学習内容を自らの言葉で記述する欄。プレースホルダに記述例を提示 |

日記欄は上記の目標タブに連動し、選択中の資格試験目標についてのみ表示する（読書目標は後述の想起入力が同じ役割を果たすため、日記欄の対象外）。当日のノルマ有無に関わらず選択中の目標がACTIVEであれば表示し、先行着手した内容を自由記述できる逃げ道を維持する。

**AI対話（下段）**

チャット形式の対話領域とする。初回の応答は、実績入力および日記の内容を確定して送信した時点で生成される。

対話は複数往復可能とする。対話終了後、確定操作により報告が確定する。

同一カテゴリの目標が2件以上同時進行している場合、AI対話（会話・プロンプト・履歴のいずれも）は選択中の1目標のみを対象とする（1.1改15、未決事項L-07の解消方針転換）。目標タブを切り替えて別の目標を選択した場合、実績入力・日記と同様にAI対話も選択中の目標分のみへ切り替わる。以前の版（改13以前）はカテゴリ単位で1本の会話を共有し、複数目標の状況をまとめて1回の応答で返す方式だったが、目標ごとに独立した会話・応答へ変更した。

**確定処理**

確定（資格試験／読書／仕事の各カテゴリの確定ボタン）により、そのカテゴリについて以下が実行される。

1. 実績数値および日記本文（資格試験のみ）を変更不可として保存
2. 対話履歴を保存
3. 当日・当該カテゴリの記録状態を報告済に変更
4. 当日中に着手している全カテゴリが報告済になった場合のみダッシュボードへ遷移。他に未確定のカテゴリが残る場合は同じ画面に留まり、確定したカテゴリのタブのみ読み取り専用表示に切り替わる

確定前に画面を離脱した場合、未確定カテゴリの入力内容は保存されない旨を警告する。

**AI応答が得られない場合**

AI基盤が利用できない場合も、確定操作を許容する。この場合、対話履歴は空となる。

**読書目標の実績入力（REP-13、REP-14）**

進行中の読書目標を選択している場合、実績入力（上段）に書籍ごとの想起欄を表示する（上記の目標タブにより資格試験目標の教材行とは排他表示となる）。

| 項目 | 内容 |
| --- | --- |
| 書名 | 表示のみ |
| 今日読んだ内容の想起 | 複数行テキスト。必須（R-65）。プレースホルダに「今日はどこまで読みましたか。印象に残ったことは何ですか」等の記述例を提示 |
| 時間枠ごとの読書時間 | 資格試験の「時間枠ごとの投下時間の入力」と同一の仕様（表示するスロット・初期値・その日限りの変更・未配分スロットの追加）。任意 |
| 読書時間（合計） | 表示のみ。時間枠ごとの入力値の合計を自動算出 |
| 現在ページ | 数値入力。任意。0以上、総ページ数以下 |

数値実績（現在ページ・読書時間）の入力は必須としない（R-65）。想起欄のみの入力でも確定できる。

ページに関する入力欄は「現在ページ」1つだけとする（1.1改16）。従来あった「読んだページ数」は廃止した。利用者がその日に読んだページ数を毎日記憶していられないという実際の利用上の問題があり、かつ読書は定量的な進捗管理を行わない目標（R-71）であるため、投下量の指標を保持する意味がないためである。現在ページは画面上の進捗表示のためだけに用い、評価の対象とはしない（下記のAI対話への差し込み情報を参照）。

読書目標で記録した時間は、実効速度・完了予測日の算出には用いない（読書はこれらを持たないため。R-71）。集計・表示・AIへの文脈提供にのみ用いる。

AI対話（下段）は資格試験と共通のUI構成を用いるが、通信先は別エンドポイント（`POST /records/{date}/reading-chat`）とし、読書用プロンプト（REP-14、17.6参照）で生成する。会話・対話履歴は用途ごと・目標ごとに分離されており（`ai_conversation`の`scope`＋`goal_id`、および`chat_message.purpose`＋`goal_id`によるフィルタリング。データ構造編5.4・5.5、ロジック・プロンプト編21.1、1.1改15）、資格試験目標と読書目標が同日に両方進行中でも、また同カテゴリの目標が2件以上進行中でも、互いの対話内容は相手のプロンプトに混入しない。

**仕事目標の実績入力（REP-15、REP-16）**

進行中の仕事目標を選択している場合、実績入力（上段）に案件ごとの業務記録欄を表示する（上記の目標タブにより資格試験・読書の入力欄とは排他表示となる）。

| 項目 | 内容 |
| --- | --- |
| 案件名 | 表示のみ |
| 本日の業務内容 | 複数行テキスト。必須（R-75）。プレースホルダに「今日はどのような業務に取り組みましたか」等の記述例を提示 |

読書と異なり、ページ数のような数値項目は持たない（要件定義書6.11本文「構造化フィールドは持たない」という設計判断）。業務内容の自由記述欄のみで確定できる。

AI対話（下段）は資格試験・読書と共通のUI構成を用いるが、通信先は別エンドポイント（`POST /records/{date}/work-chat`）とし、仕事用プロンプト（REP-16、17.8参照）で生成する。会話・対話履歴は読書と同じ仕組み（`ai_conversation`の`scope`＋`goal_id`、`chat_message.purpose`＋`goal_id`）で分離されており、資格試験・読書・仕事の各目標が同日に進行中でも、また同カテゴリの目標が2件以上進行中でも、互いの対話内容は相手のプロンプトに混入しない。

### 6.6 SC-07 進捗のみ登録

実績入力領域のみを持つ。日記記述およびAI対話領域を持たない。実績入力の構成（時間枠ごとの投下時間の入力を含む）は6.5と共通とする。

投下時間は任意入力とする。時間枠ごとの入力欄がすべて空欄の場合を未入力とし、当該日は実効速度の算出対象から除外される旨を画面上に明示する。

### 6.7 SC-08 日次報告閲覧

**構成**

SC-06と同様、着手中（ACTIVE）の目標が2件以上ある場合は画面上部に目標タブを表示し、対象目標を1件選択して切り替える（1.1（改13））。実績・日記・対話履歴は選択中の目標の種別（資格試験／読書／仕事）に応じた内容のみを表示する。着手中の目標が0〜1件の場合はタブを表示せず、従来通り全内容をそのまま表示する。

### 6.8 SC-09 分析

対象目標は、日次報告（6.5）・カレンダー（6.4）・ダッシュボード（6.1）と同じ目標タブ（GoalTabBar）で1件選択する（1.1改14）。選択中の目標のカテゴリ（資格試験／読書／仕事）に応じてタブ構成を出し分ける。

目標タブに並べる対象は、他の3画面（着手中の目標に限る）とは異なり、**クローズ済みの目標も含む**（分析は結果が出た後の振り返りにも用いるため）。ただしアーカイブ済みの目標（一覧から非表示にするための状態、R-61）と下書きの目標（実績・記録が1件も存在せずどのタブも空になる）は除外する（1.1改16）。

アーカイブ済みの目標については、画面上部に「アーカイブ済みを表示」トグル（チェックボックス）を設け、利用者が任意で目標タブに含められる（1.1改17）。既定はOFF（非表示）とし、対象となるアーカイブ済みの目標が1件もない場合はトグル自体を表示しない（目標一覧6.15と同じ操作方法）。トグルONで表示された目標のタブには、通常の目標と区別できるようアーカイブ済みである旨を併記する。下書きの目標は本トグルの対象外（ONにしても表示されない）。なお、他の3画面（6.1・6.4・6.5／6.7）は目標タブの対象を着手中（`ACTIVE`）に限定しており、7.1.1の遷移条件により「アーカイブ済みかつ着手中」の目標は存在し得ないため、これらの画面には本トグルを設けない。

| ガントチャート | 教材の開始日から締切までの帯と、現在の進捗位置 |

## 7. 状態遷移仕様

### 7.1 目標の状態遷移

```
        ┌─────────┐
        │ 下書き  │
        └────┬────┘
             │ 開始
        ┌────▼────┐
   ┌────│ 進行中  │────┐
   │    └────┬────┘    │
   │ 一時停止 │ 受験完了 │ 中断・辞退
   │         │         │
┌──▼──────┐  │  ┌──────▼──────┐
│ 一時停止 │  │  │ クローズ     │
└──┬──────┘  │  │（結果登録なし）│
   │ 復帰     │  └─────────────┘
   └─────────┘
             │
       ┌─────▼──────────┐
       │ クローズ        │
       │（結果登録あり）  │
       └────────────────┘
```

**遷移条件**

| 遷移 | 条件 |
| --- | --- |
| 下書き → 進行中 | 試験科目1件以上、教材1件以上、リソース配分が設定済み（いずれか1つ以上のスロットへ1分以上を配分していること） |
| 進行中 → 一時停止 | 制約なし。リソース配分を解放する（配分値は保持したまま、スロットの空き時間の計算対象から除外する） |
| 一時停止 → 進行中 | 配分している各スロットについて、空き時間が元の配分時間以上であること。1つでも不足する場合はエラー |
| 進行中 → クローズ（結果あり） | 全科目の受験結果が登録済み |
| 進行中 → クローズ（結果なし） | 確認モーダルでの承認 |
| クローズ → 他の状態 | 遷移不可 |

クローズへの遷移時、総括レポートの生成を非同期で開始する。生成の成否はクローズ処理の成否に影響しない。

### 7.1.1 アーカイブ状態

アーカイブは `GoalStatus` とは独立したフラグ（`archived_at`）で表現し、状態遷移図には含めない。可視性のみを制御し、`status` 自体は変化しない。

| 遷移 | 条件 |
| --- | --- |
| 進行中でない → アーカイブ | `status` が `ACTIVE` 以外（`DRAFT` / `PAUSED` / `CLOSED_WITH_RESULT` / `CLOSED_WITHOUT_RESULT`）であること（要件定義書R-61、1.1（改6）） |
| アーカイブ → 復元 | いつでも可能。復元後の `status` はアーカイブ前のまま変わらない |
| アーカイブ済み → 完全削除（物理削除） | アーカイブ済みであること。学習実績を含めて削除するか、実績が残る場合は拒否するかを選択する（データ構造編4.2） |

アーカイブ中は状態遷移操作（下書き→進行中の開始、一時停止→進行中の再開、下書きの即時削除）を拒否し、まず復元（アーカイブ解除）が必要（`activate_goal`・`resume_goal`・`delete_goal`のガード）。`ACTIVE`は元よりアーカイブ不可のため、進行中→一時停止・進行中→クローズの遷移とアーカイブ状態が同時に成立することはない。

**読書目標（category=READING）の場合の遷移条件**

状態遷移そのもの（下書き／進行中／一時停止／クローズ）は資格試験と共通の`GoalStatus`を用いるが、遷移条件は以下のとおり読み替える。アーカイブ・完全削除の遷移条件（上記7.1.1）は種別を問わず共通であり、完全削除時の実績の道連れ判定は読書目標では想起記録（reading_log）が対象となる（データ構造編4.2）。

| 遷移 | 条件 |
| --- | --- |
| 下書き → 進行中 | 書籍が1件登録済みであること（試験科目・教材は不要。リソース配分は任意のため未設定でも遷移できる。R-64） |
| 進行中 → 一時停止 | 制約なし。リソース配分を設定している場合は資格試験と同様に解放する |
| 一時停止 → 進行中 | 配分している各スロットについて、空き時間が元の配分時間以上であること。配分が未設定の場合は制約なし |
| 進行中 → クローズ（`CLOSED_WITH_RESULT`＝読了） | 書籍タブでの「読了として記録する」操作の承認（6.2、`POST /books/{id}/complete`） |
| 進行中 → クローズ（`CLOSED_WITHOUT_RESULT`＝中断） | 確認モーダルでの承認（`POST /goals/{id}/close`。資格試験の「結果なし」クローズと同一エンドポイント） |
| クローズ → 他の状態 | 遷移不可 |

`CLOSED_WITH_RESULT`は資格試験では「合否結果を伴うクローズ」を意味するが、読書では合否が存在しないため「読了という成果を伴うクローズ」という意味に読み替えて用いる（設計書 データ構造編 5.3）。`CLOSED_WITH_RESULT`への遷移時、読了レポートの生成を非同期で開始する。生成の成否はクローズ処理の成否に影響しない（資格試験の総括レポートと同じ方針）。

**仕事目標（category=WORK）の場合の遷移条件**

状態遷移そのもの（下書き／進行中／一時停止／クローズ）は資格試験と共通の`GoalStatus`を用いるが、遷移条件は以下のとおり読み替える。アーカイブ・完全削除の遷移条件（上記7.1.1）は種別を問わず共通であり、完全削除時の実績の道連れ判定は仕事目標では業務記録（work_log）が対象となる（データ構造編4.2）。

| 遷移 | 条件 |
| --- | --- |
| 下書き → 進行中 | 案件情報が1件登録済みであること（試験科目・教材・リソース配分は不要） |
| 進行中 → 一時停止 | 制約なし。仕事目標は元よりリソース配分を持たないため解放処理は発生しない |
| 一時停止 → 進行中 | 制約なし（リソースの空き確認は行わない） |
| 進行中 → クローズ（`CLOSED_WITH_RESULT`＝結果あり） | 確認モーダルでの承認（納品等の成果を伴う終了。GOL-10、`POST /goals/{id}/close`にbody `with_result=true`を指定） |
| 進行中 → クローズ（`CLOSED_WITHOUT_RESULT`＝結果なし） | 確認モーダルでの承認（中止・打ち切り。`POST /goals/{id}/close`。`with_result`省略時の既定） |
| クローズ → 他の状態 | 遷移不可 |

読書と異なり、仕事目標のクローズ操作はレポート生成の契機ではない。月次報告・半期評価は案件が進行中の間、周期的に生成する（CLS-09〜12、6.2「クローズ操作」）。クローズ後は資格試験・読書と同様に全項目を読み取り専用とするが、既に生成済みの月次報告・半期評価は引き続き閲覧・エクスポートできる。

### 7.2 日付の記録状態遷移

記録状態（未入力／進捗のみ登録済／報告済）は、日付単位ではなくカテゴリ（資格試験／読書／仕事）ごとに独立して保持する（1.1（改13））。以下の状態遷移図・入力可能期間は、日付×カテゴリの組ごとに個別に適用される。あるカテゴリを報告済にしても、同日の他カテゴリの状態には影響しない。

```
  ┌────────┐
  │ 未入力 │
  └───┬────┘
      │
      ├──[実績数値のみ入力]──→ ┌──────────────┐
      │                        │ 進捗のみ登録済 │
      │                        └───────┬──────┘
      │                                │
      │                                │ 前日以内の場合のみ
      │                                │ 日記＋対話を追加
      │                                ▼
      └──[報告一式を入力]────────→ ┌──────────┐
                                    │ 報告済    │
                                    └──────────┘
                                    （以降変更不可）
```

**入力可能期間**

| 状態 | 入力可能条件 |
| --- | --- |
| 未入力 → 進捗のみ登録済 | 対象日が当日または前日以前 |
| 未入力 → 報告済 | 対象日が当日または前日 |
| 進捗のみ登録済 → 報告済 | 対象日が当日または前日 |
| 報告済 → 変更 | 不可（当該カテゴリのみ）。コメント追加のみ可能 |

「当日」の判定には設定された1日の境界時刻を用いる。

カレンダー・ダッシュボードで表示する日単位の記録状態（1状態）は、その日に着手した全カテゴリ（一度も入力していないカテゴリは対象外）の状態から算出する集約値である。着手した全カテゴリが報告済なら報告済、1つでも進捗のみ登録済があれば進捗のみ登録済、いずれのカテゴリにも一度も入力が無ければ未入力とする。

### 7.3 受験日の状態遷移

```
  ┌──────────────┐  確定操作  ┌──────────────┐
  │ 期間（暫定）  │──────────→│ 確定日        │
  └──────────────┘            └──────────────┘
```

期間から確定日への遷移時、計画の再算出を自動的に実行する。確定日から期間への逆遷移は許容する（誤操作の訂正のため）。

### 8.2 会話の管理方針

**制約**

開発キットでは、メッセージ送信前に会話を作成し、その識別子を指定する必要がある。会話はAI基盤側に永続化される。

**方針：用途と日付ごとに会話を分離する**

| 用途 | 会話の単位 | 会話のタイトル |
| --- | --- | --- |
| 日次報告 | 1日1会話（複数目標にまたがりうるため目標非依存） | `{日付} 日次報告` |
| 週次要約 | 1週1会話（目標ごと） | `{週開始日}週 週次要約` |
| 今日の一言 | 1日1目標につき1会話（ACTIVEな目標が無い日のみ目標非依存の1件） | `{日付} 今日の一言 {目標名}` |
| 総括レポート | 目標ごと1会話 | `総括レポート` |
| 仕事日次報告 | 1日1会話（読書と同様、目標非依存。資格試験の日次報告とは別会話） | `{日付} 仕事日次報告` |
| 月次報告 | 1か月1会話（目標ごと・対象月ごと） | `{対象月} 月次報告` |
| 半期評価 | 1半期1会話（目標ごと・対象半期ごと） | `{対象半期} 半期評価` |

**方針の理由**

会話を用途ごとに分離することで、異なる目的のプロンプトが文脈として混入することを防ぐ。日次報告のフィードバックが、朝に生成した「今日の一言」の文脈に引きずられる事態を構造的に排除する。

今日の一言は目標ごとに独立した会話・プロンプト呼び出しとする（未決事項L-04）。複数目標が同時進行している場合に、他目標の情報を一切混ぜないことで、順調な目標に引っ張られて停滞している目標の実態と乖離した一言が生成されることを構造的に防ぐ。

日をまたぐ文脈は、会話の継続によってではなく、週次要約をプロンプトに注入することで実現する。この方式であれば、注入する情報量をアプリケーション側で完全に制御できる。

**フォルダによる整理**

すべての会話をフォルダ配下に作成する。目標に紐づく会話（週次要約・総括レポート・今日の一言・月次報告・半期評価）はフォルダ名「`{接頭辞}_{目標名}`」の目標別フォルダに、目標に紐づかない会話（日次報告、仕事日次報告、およびACTIVEな目標が無い日の今日の一言）は接頭辞そのものを名前とする共通フォルダに配置する。接頭辞は設定から変更可能とする。共通フォルダをAI基盤側で削除するだけで、アプリ由来の会話を一括で解放できる。

**会話識別子の保持**

作成した会話の識別子はローカルに保持する。一覧取得APIを毎回呼び出さない。

### 8.3 メッセージ送信の指定

| パラメータ | 指定値 | 理由 |
| --- | --- | --- |
| Web検索 | 無効 | 既定値が有効のため明示指定が必須。試験対策の文脈に無関係な検索結果が混入することを防ぐ |
| ナレッジ検索 | 無効 | 本アプリはアシスタントのナレッジを使用しない |
| 親メッセージ順序 | 送信するが文脈維持には用いない（8.3.1参照） | 同一日内の複数往復における文脈維持は対話履歴の注入（8.4）で実現する |
| 画像・文書・音声 | 使用しない | MVPの範囲外 |

#### 8.3.1 親メッセージ順序に関する既知の制約（要検証）

導入したAI基盤の開発キット（NewtonX ADK v0.10.5）を実際にソースコードで確認したところ、`send_message()`のメソッドシグネチャに親メッセージ順序を指定する引数が存在せず、送信内容には常に固定値0が設定されることを確認した。バンドルされた公式ドキュメント（APIリファレンス、利用ガイド、トラブルシューティング）はすべてこのパラメータが機能する前提で書かれており、ドキュメントと実装が矛盾している。

**この制約を前提に、本アプリは以下の方針を取る。**

- AI基盤側の会話スレッド機能（親メッセージ順序による文脈継承）には依存しない
- 同一日内の複数往復における文脈維持は、本アプリが独自に保持する対話履歴（`chat_message`）を毎回のプロンプトへ全文注入する方式（8.4「対話履歴」）で実現する。この方式はAI基盤側の実装状況によらず機能する
- `ai_conversation.last_parent_order` の値は将来の開発キット改修に備えて記録は継続するが、現状は文脈維持の実効性を持たない
- 回答が出力上限で途切れた場合の継続取得（開発キット側が推奨する「終端マーカー方式」）も親メッセージ順序に依存するため、本アプリでは代わりに直前の応答本文をプロンプトに含めて「続きを出力してください」と自己完結した指示で送信する方式を取る

この制約は導入したADKのバージョン（v0.10.5）に起因するものであり、将来のバージョンアップで解消される可能性がある。解消された場合は、親メッセージ順序による文脈継承を主とし、対話履歴の全文注入を縮退時のみに用いる構成へ最適化してよい。

**アシスタントへのナレッジ登録は行わない。** アシスタントが組織内で共有される可能性があり、個人の学習記録を登録することは不適切である。

### 8.5 プロンプトの段階的縮退

**制約**

AI基盤の入力上限は明示されていない。

**方針**

プロンプトを組み立てた後、文字数が設定値を超える場合、以下の順序で情報を削減する。

| 順位 | 削減対象 | 理由 |
| --- | --- | --- |
| 1 | 古い週次要約から順に除外 | 直近ほど関連性が高い |
| 2 | 教材情報の詳細度を下げる | 締切が遠い教材を集約表示にする |
| 3 | 当日の対話履歴を古い往復から除外 | 直近の往復が最も重要 |
| 4 | 日記本文を末尾優先で切り詰める | 完全な除外は避ける |

縮退が発生した場合、その旨を画面上に控えめに表示する。利用者が「なぜ言及されない情報があるのか」を把握できるようにするためである。

### 8.6 応答に対する要求

定型プロンプトは、以下を満たす応答を得るように構成する。

| 要求 | 内容 |
| --- | --- |
| 状況の解釈 | 数値実績と自然言語記述を統合し、進捗の背景要因を推定する |
| 成長の指摘 | 過去の記述との比較により、説明の解像度や構造化の変化を指摘する |
| 行動の提案 | 翌日以降の具体的な行動を提案する |
| 双方向の調整 | 負荷を増やす提案と減らす提案の双方を選択肢として持つ |

**負荷を減らす提案の段階**

| 段階 | 提案内容 |
| --- | --- |
| 軽 | 特定期間の負荷係数の引き下げ |
| 中 | 教材の優先順位変更、学習範囲の絞り込み、予定周回数の削減 |
| 重 | 受験日の後ろ倒し、目標の一時停止 |
| 即時 | 当日の休息 |

### 8.7 認証

**認証方式はPersonal Access Token（PAT）を主とする。** 導入した開発キット（NewtonX ADK）の現行の公式利用ガイドは、Host（サブドメイン）とPATによる認証を標準的な方法として案内しており、ブラウザ経由のOAuth／デバイスコード認証はEntraID構成時のフォールバック経路として内部に残るのみである。当初の設計はブラウザ認証を主経路と想定していたが、公式情報にあわせて以下のとおり改める。

| 項目 | 方針 |
| --- | --- |
| 認証情報の管理 | 開発キットの仕組みに委ねる。独自の資格情報管理を実装しない。Host（例: `xxx.newton-x.net`）とPATは、設定画面（SC-11）から開発キットの設定へ反映する |
| PATの発行 | NewtonXのWeb版アカウント画面で利用者自身が発行する（本アプリからは発行できない）。設定画面に発行手順への案内を表示する |
| 起動時 | Host・PATが設定済みかを確認する。開発キットはPAT設定時、他の認証手段より優先してこれを使用する |
| 未設定・無効時 | 設定画面でHostとPATの入力を促す。フォールバックとしてブラウザ経由の認証フロー（バックグラウンドスレッドで実行）を提供するが、主経路としては使用しない |
| 認証状態の公開 | クライアントには真偽値のみを返す。PAT・トークンは送出しない |
| リダイレクト先（フォールバック時のみ） | 開発キットの既定値（ローカル8400番）を使用する。アプリケーションサーバは別ポート（8100）で起動する |

### 8.8 エラー処理

| エラー種別 | 応答コード | 画面での扱い |
| --- | --- | --- |
| 未認証・トークン期限切れ | AI_AUTH_REQUIRED | 設定画面での再認証を促すメッセージを表示 |
| タイムアウト | AI_TIMEOUT | 再送ボタンを表示。実績入力の内容は保持する |
| 通信エラー・頻度制限 | AI_ERROR | エラー内容を表示。再送ボタンを表示 |
| 会話操作の失敗 | AI_ERROR | 同上 |
| 設定不備 | AI_CONFIG_ERROR | 設定画面への遷移を促す |

**実装上の注意（タイムアウトの判定方法）**

導入した開発キットの例外クラスは `NewtonXError` / `AuthenticationError` / `APIError` / `ConfigurationError` / `FileUploadError` / `ChatError` の6種であり、タイムアウト専用の例外クラスは存在しない。通信タイムアウトも内部的に `APIError` へ一律ラップされるため、型による判定はできない。本アプリでは、呼び出し側で計測した経過時間が設定値（`ai.timeout_seconds`）を超えているか、またはエラーメッセージにタイムアウトを示す文字列が含まれるかによって `AI_TIMEOUT` を判定する。

**重要な制約**

AI呼び出しの失敗により、実績入力の内容が失われてはならない。日次報告画面では、実績と日記の入力内容をクライアント側の状態として保持し、AI応答の成否とは独立させる。

AI応答が得られない状態でも、報告の確定を許容する。AIとの対話は本アプリの中核だが、それが利用できないことを理由に記録自体が失われるのは本末転倒である。

### 8.9 呼び出し頻度の制御

頻度制限が存在する可能性があるため、連続する呼び出しの間隔に下限を設ける。既定値は2秒とする。

週次要約の遡及生成では複数回の呼び出しが連続するため、この制御が特に重要となる。

### 8.9.1 用途別アシスタントの選定（実機確認済み）

連携箇所（8.1）ごとに既定のアシスタントを設定する。全用途を単一アシスタントに固定せず、`get_assistants()`が返す各アシスタントの説明文に基づき、タスク特性に合ったものを既定値とする。

| 連携ID | 用途 | 既定アシスタント | 選定理由 |
| --- | --- | --- | --- |
| AI-01 | 日次報告フィードバック | GPT-5.4（高性能） | 複雑なタスクの整理や具体的な提案に適しており、状況解釈・成長の指摘・行動提案という要求（8.6）に合致する |
| AI-02 | 週次要約生成 | Gemini 2.5 Flash（高速） | 要約に適した特性を持ち、起動時の複数週遡及生成（速度が重要）に適する |
| AI-03 | 今日の一言生成 | GPT-5.4-mini（高速） | 速度と情報整理のバランスに優れ、ダッシュボードでの非同期表示に適する |
| AI-04 | 総括レポート生成 | GPT-5.4（高性能） | AI-01と同様、低頻度・高品質重視のタスクのため同一アシスタントとする |
| AI-06 | 読書日次報告フィードバック | GPT-5.4-mini（高速） | 想起の言語化を助ける対話であり、負荷は低いためAI-03（今日の一言）と同系統の高速寄りアシスタントとする |
| AI-07 | 読了レポート生成 | GPT-5.4（高性能） | AI-04と同様、低頻度・高品質重視のタスクのため同一アシスタントとする |
| AI-08 | 仕事日次報告フィードバック | GPT-5.4-mini（高速） | AI-06（読書日次報告フィードバック）と同一アシスタント。要件定義時点で「読書機能同様に日々の頑張りを労うフィードバック」と明示されており、高頻度・低負荷という性質もAI-06と一致する |
| AI-09 | 月次報告ドラフト生成 | 未定（実環境での疎通確認後に選定） | AI-04・AI-07と同様、低頻度・高品質重視のタスク |
| AI-10 | 半期評価レポート生成 | 未定（実環境での疎通確認後に選定） | AI-09と同様、低頻度・高品質重視のタスク |

各アシスタントの識別子は `app_setting`（`ai.assistant_uid.*`、設計書 データ構造編 5.2）に既定値として保持し、設定画面（SC-11）から用途ごとに変更できる（Phase16実装済み、AI-08〜AI-10はPhase22実装予定）。AI-06〜AI-10の既定値は空欄のまま初期投入されており、8.9.1本文の非対応アシスタント一覧を踏まえ、実環境（Phase11相当の疎通確認）で軽量な疎通テストを行った上で選定する。

**既知の非対応アシスタント**：導入済み環境で以下2件は`send_message`が常に失敗することを実機確認済みである。設定画面の選択肢から除外するか、選択・保存時に疎通確認を行うことが望ましい。

| アシスタント名 | 状態 |
| --- | --- |
| GPT-4o mini（高速） | 使用不可（404で確認済み） |
| GPT-4o（高性能） | 使用不可（404で確認済み） |

この一覧は将来変動しうるため、ハードコードした除外リストのみに頼らず、送信失敗時のエラーハンドリング（8.8のAI_ERROR、再送・再選択の導線）で汎用的に吸収できる設計とする。

## 10. バリデーション方針

| 対象 | 方針 |
| --- | --- |
| 必須項目 | 入力欄単位で即時検証し、未入力を明示する |
| 数値範囲 | 品質指標は0〜100、負荷係数は正の数、総量および完了量は0以上、予定周回数は1以上の整数 |
| 日付整合 | 教材の開始日が締切より後の場合、保存を拒否する |
| 日付整合 | 受験日の期間開始日が期間終了日より後の場合、保存を拒否する |
| 周回整合 | 予定周回数を、既に完了した周回数を下回る値に変更できない |
| 完了量 | 累積完了量が総作業量を超える入力を警告する。保存は許容する（見積もり誤差の吸収のため） |
| リソース | 配分時間は0以上の整数（分）とする。スロットごとの配分合計がそのスロットの連続時間を超える保存を拒否する（NT-04）。ただしスロット側の短縮・削除による事後的な超過は警告のみとし保存を許容する（NT-09） |
| 時間表示 | 分から時間へ換算して表示する箇所は、小数第2位以下を切り捨てて小数第1位まで表示する（四捨五入しない）。算出には常に分（整数）を用いる |
| 遡及入力 | 前日を超える過去日への入力を拒否する |
| 変更不可 | 報告済の日およびクローズ済の目標への更新要求を拒否する |
| 時刻 | 1日の境界時刻は0時から11時の範囲とする |
| 読書：書籍 | 総ページ数は必須とし、1以上の整数とする |
| 読書：想起 | 想起本文は必須、現在ページは0以上・総ページ数以下の整数とする（任意入力） |
| 読書：冊数 | 1目標に対して書籍を2件以上登録できない |
| 仕事：案件情報 | 想定業務内容・着手日は必須。取引先・案件の呼称は任意 |
| 仕事：業務記録 | 業務内容の自由記述は必須（数値項目は持たないため他の数値バリデーションは適用対象外） |
| 仕事：案件数 | 1目標に対して案件情報を2件以上登録できない |
