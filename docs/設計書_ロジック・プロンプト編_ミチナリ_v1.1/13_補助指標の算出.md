## 13. 補助指標の算出

### 13.1 バッファ消費率

```
経過バッファ日 = { d | goal.start_date ≤ d < T かつ type(d) = BUFFER }

実績あり日 = 経過バッファ日のうち、goal g 配下の教材の study_log が
             1件以上存在する日

buffer_usage_rate = |実績あり日| / |経過バッファ日|
```

**目標による絞り込み（1.1（改13））**：実績あり日の判定は、対象目標 g 配下の教材（material.goal_id = g.id）に紐づく `study_log` のみを数える。目標で絞り込まないと、同時進行している別目標の実績によってバッファ日が消費済みと判定され、目標ごとの余裕度を表さない値になる。

**適用範囲**：本指標は `category = EXAM` の目標にのみ適用する。読書・仕事目標は日種別（第4章）による計画運用の対象外であり（要件定義書R-71・R-74、21.1・22.1）、バッファという概念自体を持たないため算出しない（算出結果は「なし」とし、画面にも表示しない）。

なお、週次要約の `{{week_metrics}}`（17.3）が示すバッファ消費状況は、集計窓が「週内」である点だけが本指標と異なる同一の算出であり、実装は共通化する。

**意味**

余裕度の直接指標である。バッファをほとんど使わずに計画通り進んでいれば余裕があり、毎週末フルに使ってようやく維持している状態であれば計画自体が過密である。

この指標はAIへの入力に含める。数値実績のみからは「計画が重すぎる」という判断は困難だが、バッファ消費率が高止まりしていれば、それは計画の設計そのものに問題があることを示す。

### 13.2 進捗率

```
progress_rate(m) = C(m) / TW(m)
```

教材の単位が「問」「ページ」「回」と異なるため、目標単位の進捗率は単純合算では意味を持たない。ダッシュボードでは教材別に表示し、目標単位では「教材ごとの進捗率の平均」を参考値として表示する。

### 13.3 報告率（KPI）

```
report_rate(g) = (goal g のカテゴリに対応する記録状態列（exam/reading/work_record_state）が
                   REPORTED の日数)
                 / (goal.start_date から T までの日数)
```

要件定義書に定めたKPIである。記録状態はカテゴリ（資格試験／読書／仕事）ごとに独立しているため（データ構造編5.4、1.1（改16））、目標gの報告率は必ずgのカテゴリに対応する列のみを参照する。他カテゴリの確定状況は混入させない（例: 資格試験を確定していない日でも、その日に仕事を確定していれば仕事目標の報告率にはカウントする）。

### 13.4 連続報告日数

```
T から遡り、goal g のカテゴリに対応する記録状態列が REPORTED である日が連続する日数。
type(d) = BUFFER または OFF の日は、報告がなくても連続を中断しない。
```

バッファ日に報告しないことは想定された行動であり、それによって連続記録が途切れるのは設計思想（バッファの非対称性）に反する。

### 13.5 リプラン回数

```
replan_count(g) = plan_baseline のうち、goal 配下の material に属し、
                  reason ≠ INITIAL であるレコード数
```

総括レポートおよびエクスポートに含める。
