## 26. 節目のお祝いの判定ロジック

本章は、記録が節目に届いたときにキャラクターと一緒にお祝いする機能（開発Todo「節目のお祝い」v1.0、要件定義書6.18 R-132〜R-137、仕様書6.5・6.8・6.11）の判定ロジックを定義する。判定は`backend/app/services/milestone_service_common.py`（3種別共通の節目）と`milestone_service_exam.py`／`milestone_service_reading.py`／`milestone_service_work.py`（種別固有の節目）が担い、到達した事実のみを`goal_milestone_achievement`テーブルへ記録する（データ構造編9章参照）。AIは使用しない。

### 26.1 共通

- 判定のタイミング：記録確定（`POST /records/{date}/finalize`・`/reading-finalize`・`/work-finalize`）が成功した直後、既存のコミットより前に、対象カテゴリのACTIVE目標すべてについて判定・永続化する（`DailyRecord`はカテゴリ別の確定状態を日付単位で1行持つのみで目標には紐付かないため、確定処理を呼んだ1目標だけでなく同カテゴリの全ACTIVE目標が対象になる）。「今日は何もしていない」ボタン（ゼロ記録）による確定も同じ経路を通る。
- 閾値：すべて`app_setting`（カンマ区切りの整数文字列）に外部化する（26.3参照）。現在値が閾値以上であれば、その閾値ごとに1件の節目として記録する。
- 重複防止：`goal_milestone_achievement`は`(goal_id, milestone_type, milestone_key)`の一意制約を持ち、同じ節目は二度記録されない。到達済みだが未お祝い（`celebrated_at`がNULL）の節目は、分析画面の一覧取得時とは別に、`GET /goals/{goal_id}/milestones/pending-celebrations`（読み取りのみ、副作用を持たない）で取得し、モーダルで表示後に`POST /goals/{goal_id}/milestones/{milestone_id}/celebrate`でお祝い済みにする。
- 既存利用者への大量表示防止：起動時（`bootstrap_database`、初期データ投入の直後）に一度だけ、全目標の現在到達済み節目を同じ判定関数で算出し、到達日時・お祝い済み日時の両方を起動時刻としてまとめて記録する（一度きりフラグ`milestone.backfill_completed`で以後は実行しない）。これにより、導入時点までに届いていた節目は新規のお祝いとして表示されない。

### 26.2 節目の種類と算出

| 節目種別 | 対象 | 算出 |
| --- | --- | --- |
| 連続記録日数 | 3種別共通 | `metrics_service.compute_consecutive_report_days`（`GET /dashboard`の統計サマリ`GoalStatsRead.consecutive_report_days`と同じ値。`DailyRecord`のカテゴリ別状態列のみを見るため、「何もしていない」記録・予備日でも連続記録が維持される） |
| 累計記録日数 | 3種別共通 | 目標開始日から当日までの範囲で、`DailyRecord`の当該カテゴリ状態列がREPORTEDの日数をカウント |
| 累計ページ数 | 読書 | `book_service.sum_cumulative_pages_read`。利用者の読書全体（lifetime、複数の読書目標にわたる累計）が対象。各書籍の最新（日付降順の先頭）の現在ページを合計する |
| 読了した冊数 | 読書 | `book_service.count_completed_books`。読書全体が対象。`category=READING`かつ`status=CLOSED_WITH_RESULT`（読了）の目標数（`Book.goal_id`にUNIQUE制約があり1目標=1冊のため、目標の完了件数がそのまま冊数になる） |
| 教材1周完了 | 資格試験 | `cycle_service.compute_completed_cycles`。閾値を持たないイベント型で、教材×完了済み周回番号の組ごとに1件（`milestone_key`="{material_id}:{cycle_number}"） |
| 目標全体の進捗率(%) | 資格試験 | `metrics_service.compute_goal_overall_progress_rate`（ダッシュボードの目標カードの進捗率と同じ「教材ごとの値の平均」、13.2） |
| 記録件数 | 仕事 | `work_service.count_work_records`。案件（`WorkAssignment`）に紐づく`WorkLog`の件数 |
| 評価期間を通して記録し続けたこと | 仕事 | 閾値を持たないイベント型。直近に終了した半期（`work_report_service.previous_semiannual_period_key`）の6ヶ月すべてに、非匿名の月次報告（`GoalRetrospective`、`period_type=MONTHLY`）が存在する場合に1件（`milestone_key`=半期のperiod_key）。進行中の半期は対象外（期間が終わるまで「通して」出し続けたかどうかを確定できないため） |

### 26.3 閾値の外部化（app_setting）

既存の`app_setting`は単一スカラー値のみを持つ（配列・JSON型の実運用実装が無い）ため、閾値はカンマ区切りの整数文字列として`AppSettingValueType.STRING`に保存する。

| キー | 初期値 |
| --- | --- |
| `milestone.consecutive_days_thresholds` | `3,7,14,30,50,100,200,365` |
| `milestone.total_record_days_thresholds` | `10,30,100,365` |
| `milestone.reading_total_pages_thresholds` | `500,1000,3000,5000,10000` |
| `milestone.reading_completed_books_thresholds` | `1,3,5,10` |
| `milestone.exam_overall_progress_thresholds` | `25,50,75` |
| `milestone.work_record_count_thresholds` | `10,50,100` |

### 26.4 お祝いの表現

- 表示手段：モーダル（既存のトーストは`info`/`error`の2variantで4〜8秒の自動消滅のため、特別感を伝える用途には使わない）。手動で閉じるまで表示する。複数の節目に同時到達した場合は1件ずつキューで順に表示する。
- キャラクター：既存のキャラクターアイコン11種（アイコンセット仕様書v1.0）のうち、目標種別に応じた`exam`/`reading`/`work`アイコンを表示する。新規イラストは追加しない（目標「完了」専用の`achieved`アイコンとは意味を区別する）。
- 演出：紙吹雪風のCSSアニメーション（画像を使わない装飾）を重ねる。`prefers-reduced-motion`が有効な場合はアニメーション要素自体を描画しない（R-137）。
- 文言：「続いていること」を褒める表現のみとし、途切れたことを責める表現は使わない（R-135）。固定のロケール文言（`milestone.*`）のみで完結し、AIは使用しない。
