### 17.10 半期評価レポート（GOAL_RETROSPECTIVE_WORK_SEMIANNUAL）

読書には無い、仕事目標に固有のもう一つの周期。会社の人事評価サイクル（3月に目標設定、8月に評価。9月に目標設定、2月に評価）に合わせ、半期を「3月〜8月」「9月〜翌2月」と区切る（一般的な暦半期・会計年度の上期下期とは異なる。要件定義書R-79）。

月次報告（17.9）と同じ設計方針（2026-09-04改訂）を踏襲する。「当該半期の目標」欄はAIに書かせず、アプリケーション層が前半期の`next_goal_text`をそのまま複製する。AIが担うのは「達成度の判定」「業務内容の要約」「振り返り文の生成」「次半期の目標案の提示」の4点のみ（月次と異なり「報告・連絡事項」は半期評価の対象としない。要件定義書R-79に定めがないため）。

**注入する変数**

| 変数名 | 内容 |
| --- | --- |
| `{{work_summary}}` | 案件名、取引先・案件の呼称（任意）、想定業務内容、着手日 |
| `{{target_period}}` | 対象半期（表示用。"YYYY年3月〜8月"または"YYYY年9月〜YYYY年2月"形式。period_key（"YYYY-H1"／"YYYY-H2"）から導出する） |
| `{{target_goal_text}}` | この半期の目標（アプリが前半期の`next_goal_text`から複製済み。前半期の記録が無い初回は「（前半期の記録が無いため、今回は目標との比較を行いません）」を注入する） |
| `{{weekly_summaries}}` | 対象半期のうち既に週次要約が生成済みの範囲の圧縮表現（22.4「圧縮境界の解決」、L-11。最大6ヶ月分の生ログ注入となるこの用途で最も効果が大きい） |
| `{{period_logs}}` | 週次要約がまだ及んでいない直近部分の `work_log.body` を日付順に連結したテキスト（月次報告のロールアップではなく生の日次記録を直接参照する。22.4参照） |
| `{{anonymize}}` | 匿名化の指示（匿名化版生成時のみ） |

**AI応答の形式契約**：17.9と同じ方式。バックエンドが以下4つの見出し文字列で応答を機械的に抽出する。「達成度」の判定基準・出力形式（半角数字1文字、比較対象が無い場合は「対象外」）も17.9と同一とする。

```
## 業務内容の要約
## 達成度
## 達成状況の振り返り
## 次半期の目標
```

# このドラフトの目的

このドラフトは、働き手が社内の半期評価フォームに
転記するための下書きです。そのまま提出されることは
想定していません。

# 出力する節（この順序・この見出し文字列を厳守してください）

## 業務内容の要約
半期を通じた業務内容を整理し、時期による変化や
取り組みの推移が分かるようにまとめてください。
月次報告のロールアップではなく、日々の記録そのものを
根拠にしてください。

## 達成度
「{{target_period}}の目標」に対し、業務記録から読み取れる
達成度を、以下の基準で半角数字1文字のみで判定してください。
目標が「（前半期の記録が無いため、今回は目標との比較を行いません）」
の場合は、この節を半角数字ではなく「対象外」とだけ出力してください。

1: 達成度121%以上
2: 達成度101〜120%
3: 達成度85〜100%
4: 達成度60〜84%
5: 達成度0〜59%

## 達成状況の振り返り
上記の達成度をどう判断したか、根拠を記述してください。
可能な限り、業務記録に現れる定量的な情報を根拠として
引用してください。

## 次半期の目標
この半期の記録を踏まえ、次の半期に取り組むべき内容の案を
具体的に提案してください。断定的な指示ではなく、
働き手が採否を判断できる提案として記述してください。
可能な限り、件数や期限など定量的に判定できる形で
提案してください。
