### 17.16 単語帳由来の復習クイズ生成（VOCAB_QUIZ_GENERATE）（1.1（改70）、開発Todo_単語帳_v1.0 要件B）

単語帳のカード（用語・意味・別名、利用者の自由入力）を材料に、今日の復習専用の4択クイズを作る（単語帳の問題集〈要件A、30章〉はAIを使わない別機能であり、本節とは独立。B-U4）。起動時バッチ（`main.run_ai_startup_tasks`、17.15のテーマ由来クイズ生成の直後）、または単語帳詳細ページの「今日の復習の問題を作る」ボタンから実行する（`vocab_quiz_generation_service.run_all`・`generate_for_deck`）。アシスタントは17.15と同じ既存の週次要約用（資格試験のみ、単語帳はEXAM専用のため読書版は使わない）を流用する。会話のスコープは`VOCAB_QUIZ_GENERATE`とし、スコープキーは単語帳IDごとに分ける（`deck-{id}`）。

**対象カードの選定**：ACTIVEな資格試験の目標の、`use_in_ai=True`の単語帳に属する、まだ`quiz_question`を1件も持たないカード。優先順はチェック付き→新しく登録した順（`is_checked DESC, id DESC`、B-D8）。起動時バッチは対象ゴール横断の合計件数に対して`vocab.quiz_cards_per_startup`（既定20）枚までとする（登録が多い利用者でAI呼び出しが膨大になることを防ぐ、B-D9）。ボタンからの生成は、そのデッキ単独に同じ上限を適用する。

**入力**：対象カードを、17.14・17.15と同じ`recap_service.chunk_by_chars`（予算は既存の`recap.classify_chunk_chars`を流用）でチャンク化する。各カードは「#カードID 用語／意味／別名」の1行（別名が無ければ「／別名」部分を省略、複数別名は「、」で連結、B-D10）とする。行の組み立て（`_format_card_line`）は、17.15.2と同じ2段の変換を行う：①`vocab_service.flatten_for_single_line`で用語・意味・各別名に含まれる改行等の行区切り文字を半角空白へ変換する（「#カードID 用語／意味」という1行形式の構造を崩させず、他カードの行を偽装できないようにする。injection-reviewerレビューで検出、2026-11-18）。②`question_safety.DELIMITER_REPLACEMENTS`（山括弧の全角化）を適用したうえでリクエストごとの乱数区切り`<<<CARDS-{{nonce}}>>>`・`<<<END-CARDS-{{nonce}}>>>`で囲む（17.15.1・17.15.2と同じ二重防御）。禁止語を含むカードは送らない。

**出力の契約**：17.15と同じ5フィールド＋出典の形式だが、出典は「出典: #カードID」とする（日付ではない）。

```
問題: <問題文>
選択肢1: <text>
選択肢2: <text>
選択肢3: <text>
選択肢4: <text>
正解: <1〜4>
解説: <text>
出典: #<カードID>
```

**解析・検証**：ブロック分割・5フィールド抽出は17.15と共通の`quiz_block_parsing.parse_question_blocks`を使う。出典（`#カードID`形式）の実在検証・根拠検証は本節独自に行い、以下のいずれかに該当するブロックは個別に破棄する（1ブロックの不正でバッチ全体を無効にしない）。

1. 出典が「#数字」の形式でない（`^#(\d+)$`に一致しない）
2. 出典のカードIDが、その回に実際に送ったカードIDの集合に含まれない
3. 4つの選択肢が、正規化後（`normalize_for_vocab_match`）にすべて異なるわけではない（重複がある）
4. 出典カードの用語または別名（正規化後）が、問題文または正解の選択肢のいずれにも含まれない（根拠が無い、AIの作り話を排除する）
5. 1回の生成（1チャンクへの応答）で、同じカードIDを出典とする2問目以降（1枚のカードにつき1問まで）

採用されたブロックのみ`quiz_question`として保存する（`vocab_card_id`を設定、`theme_id`・`citation_date`はNULL、`interval_index=0`、`next_due_date`は生成日＝即時出題可能）。

**解析の正規表現の安全性**：17.15.1と同じ共通モジュール（`quiz_block_parsing.py`）を使うため、ReDoS対策（`[^\n]+?`・`re.DOTALL`不使用・`_MAX_BLOCK_CHARS`）はそのまま引き継がれる。敵対的な繰り返し入力でも1秒以内に完了することをテストで確認する（開発Todo_単語帳_v1.0 要件B §5 完了条件）。

**失敗耐性**：デッキ単位で取り消して続行する（1デッキの失敗が他デッキを止めない。`vocab_quiz_generation_service.run_all`、17.14・17.15の`run_all`と同方式。例外は握り潰してログに残し、次回の起動時バッチで再試行する）。送信前にプロンプトが`ai.max_prompt_chars`を超える場合は送信せず中止する（切り詰めない、17.14・17.15と同方式）。

**カード編集・削除・`use_in_ai`変更時の扱い**：30.8（単語帳の判定・出題ロジック）を参照。

**出題・成績への反映**：17.15.3（出題の合算と出題順）参照。単語帳由来の問題の出題・解答は、単語帳の問題集の成績（`vocab_answer_log`）には一切影響しない（B-U3）。

設定（既存のシードで未登録分のみ追加）: `vocab.quiz_cards_per_startup`（既定20）、`vocab.quiz_reference_max_chars`（既定2000、17.15.2「参考用語」用）。いずれも設定画面（SC-11）からの変更経路は設けない（17.15と同様、内部パラメータとして扱う）。

### 17.16.1 脅威モデル（STRIDE、スキル`threat-model`に従う）

本機能は、単語帳のカード（利用者が入力した用語・意味・別名）を外部AI（NewtonX）へ送り、生成されたクイズを永続化し、画面に表示する新規の経路である。データフロー・STRIDE分析は17.15.1の表へ統合して記載する（単語帳固有の脅威は同表の該当行、下記2行）。信頼境界は17.15.1と同じ（利用者の入力→外部AI、AIの出力→保存・表示の2か所）。本アプリは単一利用者・ローカル運用のため、利用者間の権限分離は対象外。

単語帳固有の対策の要点（詳細は17.15.1の表）：

- カード内容のプロンプト注入対策：山括弧の全角化＋nonce区切りの二重防御、禁止語を含むカードを送らない。根拠検証（出典カードの用語・別名が問題文・正解の選択肢に実際に含まれる）により、注入に従った出力であっても根拠が無ければ破棄される。
- 改行による「1行形式」の構造偽装対策：`vocab_service.flatten_for_single_line`で改行等を半角空白へ変換してから埋め込む（17.15.1の表参照）。
- 他目標・他単語帳のカードの混入対策：対象カード選定・出題クエリのいずれもクエリ時点で`use_in_ai`・`goal.status`・`goal.category`を再評価する（条件自体は`vocab_service.ai_eligible_deck_conditions`へ共通化）。

**受容したリスク**：単語帳カードは利用者本人の入力（既存のAI機能全般と同じ受容済みリスク）であり、本機能固有の追加の情報開示リスクは無い（単一利用者ローカル運用のため、他者への漏洩経路が無い）。
