### 17.9 月次報告ドラフト（GOAL_RETROSPECTIVE_WORK_MONTHLY）

読書の読了レポート（17.7）と異なり、クローズ時の1回きりではなく、案件が進行中の間、月次で繰り返し生成する（要件定義書R-78）。

**AIの役割を絞り込む設計**（2026-09-04改訂）：月次報告の「当月の目標」欄は、AIに書かせず**アプリケーション層が前月の`next_goal_text`をそのまま複製する**（データ構造編5.4「WORKでの流用」）。AIに前回の目標を要約させると、月をまたぐたびに言い回しが微妙にブレる（AIが自らの前回出力を言い換える過程で意味が変質する）リスクがあるため、目標文言そのものの一貫性はAIの生成に頼らない。AIが担うのは「達成度の判定」「業務内容の要約」「振り返り文の生成」「来月の目標案の提示」「報告・連絡事項の抽出」の5点のみである。

**注入する変数**

| 変数名 | 内容 |
| --- | --- |
| `{{work_summary}}` | 案件名、取引先・案件の呼称（任意）、想定業務内容、着手日 |
| `{{target_month}}` | 対象月（表示用、"YYYY年M月"形式） |
| `{{target_goal_text}}` | この期間の目標（アプリが前月の`next_goal_text`から複製済み。前月の記録が無い初回は「（前月の記録が無いため、今回は目標との比較を行いません）」を注入する） |
| `{{weekly_summaries}}` | 対象月のうち既に週次要約が生成済みの範囲の圧縮表現（22.4「圧縮境界の解決」、L-11） |
| `{{month_logs}}` | 週次要約がまだ及んでいない直近部分の `work_log.body` を日付順に連結したテキスト（22.4参照） |
| `{{anonymize}}` | 匿名化の指示（匿名化版生成時のみ） |

**AI応答の形式契約**：バックエンドが応答から5つの節を見出し文字列で機械的に抽出し、`goal_retrospective`の構造化列（データ構造編5.4）へ格納する。見出し文字列は以下の5つに固定し、順序も変更しない。

```
## 業務内容の要約
## 達成度
## 達成状況の振り返り
## 来月の目標
## 報告・連絡事項
```

「達成度」の節は、半角数字1文字（1〜5）のみを出力し、他の文言を含めない。

# このドラフトの目的

このドラフトは、働き手が社内の月次報告フォームに
転記するための下書きです。そのまま提出されることは
想定していません。働き手が最終的に手を加えて仕上げる
前提で、事実に基づいた具体的な記述を心がけてください。

---

# 出力する節（この順序・この見出し文字列を厳守してください）

## 業務内容の要約
記録から読み取れる業務内容を、時系列またはテーマ別に
整理して要約してください。想定業務内容（案件情報）と
実際の業務内容が異なる場合、その違いにも触れてください。

## 達成度
「{{target_month}}の目標」に対し、業務記録から読み取れる
達成度を、以下の基準で半角数字1文字のみで判定してください。
目標が「（前月の記録が無いため、今回は目標との比較を行いません）」
の場合は、この節を半角数字ではなく「対象外」とだけ出力してください。

1: 達成度121%以上
2: 達成度101〜120%
3: 達成度85〜100%
4: 達成度60〜84%
5: 達成度0〜59%

## 達成状況の振り返り
上記の達成度をどう判断したか、根拠を記述してください。
可能な限り、業務記録に現れる定量的な情報（件数、時間、
完了した作業量など）を根拠として引用してください。
定量的な情報が記録に無い場合は、それ自体を明記した上で
定性的な判断根拠を記述してください。

## 来月の目標
今月の記録を踏まえ、来月に取り組むべき内容の案を
具体的に提案してください。働き手が採否を判断できるよう、
断定的な指示ではなく提案として記述してください。
可能な限り、件数や期限など定量的に判定できる形で
提案してください。

## 報告・連絡事項
業務記録の中に、社内（上長等）へ報告・連絡したほうが
よいと思われる内容（懸念事項、対応が必要な事象、
特筆すべき出来事など）があれば記述してください。
該当する内容が無い場合は、この節を空欄にしてください。

---

  事実の記述に留めてください
- 社内の第三者（上長等）が読むことを想定した、
  簡潔で具体的な文体にしてください
