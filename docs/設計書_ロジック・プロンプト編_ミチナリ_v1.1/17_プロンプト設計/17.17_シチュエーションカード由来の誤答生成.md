### 17.17 シチュエーションカード由来の誤答生成（VOCAB_SITUATION_QUIZ_GENERATE）（1.1（改76）、開発Todo_単語帳_v1.0 要件F）

シチュエーションカード（見出し・状況・問い・最善の対応・解説、利用者の自由入力）を材料に、今日の復習専用の4択クイズを作る。17.16（VOCAB_QUIZ_GENERATE）が4択すべてをAIに作らせるのに対し、本節は問題文（状況＋問い）・正解（最善の対応）・解説を登録した文のまま使い、**AIには誤答の選択肢3つだけを作らせる**点が異なる（F-U5、ハルシネーションが正解・問題の前提に混入するリスクを避ける）。起動時バッチ・単語帳詳細ページの「今日の復習の問題を作る」ボタンの両方から、17.16と同じ呼び出し（`vocab_quiz_generation_service.generate_for_deck`・`run_all`）の中で実行する。会話のスコープは`VOCAB_SITUATION_QUIZ_GENERATE`、スコープキーは`deck-{id}-situation`（17.16の`deck-{id}`と区別する）。

**対象カードの選定**：17.16と共通の選定クエリ（`_candidate_cards_query`・`_select_eligible_cards`、ACTIVEな資格試験の目標・`use_in_ai=True`・まだ`quiz_question`を持たない・チェック付き→新しく登録した順）で、用語カード・シチュエーションカードの両方を一括取得したうえで、呼び出し側（`_split_by_card_type`）が種類で分ける。`vocab.quiz_cards_per_startup`の上限は分割前の合計に対して1回だけ適用する（F-D12）。

**入力**：対象カードを17.16と同じ`recap_service.chunk_by_chars`でチャンク化する。各カードは「#カードID 状況／問い／最善の対応」の1行とする（`_format_situation_card_line`）。問いが空のときは既定文言「最善の対応は？」に差し替える（`vocab_service.resolve_situation_question_text`）。状況・問いの改行は、17.16と同じ`flatten_for_single_line`で半角空白へ変換してから埋め込む（複数行専用の変換関数は作らず、既存の「1カード=1行」区切り構造の健全性を優先する、F-D10）。山括弧の全角化（`DELIMITER_REPLACEMENTS`）・リクエストごとの乱数区切り（`<<<CARDS-{{nonce}}>>>`）は17.16と同じ二重防御。禁止語を含むカードは送らない（禁止語検索の対象文字列は見出し・状況・問い・最善の対応・解説の5項目、F-D16）。

**出力の契約**：17.16とは異なる4フィールド1ブロックの形式とする。

```
出典: #<カードID>
誤答1: <text>
誤答2: <text>
誤答3: <text>
```

**解析・検証**：ブロック分割は17.15・17.16と共通の区切り（`===`）・ブロック長上限（`_MAX_BLOCK_CHARS`）を共有するが、フィールド構成が異なるため解析関数・データクラスは別とする（`quiz_block_parsing.parse_distractor_blocks`・`ParsedDistractorBlock`、F-D11）。以下のいずれかに該当するブロックは個別に破棄する。

1. 出典が「#数字」の形式でない
2. 出典のカードIDが、その回に実際に送ったカードIDの集合に含まれない、または**そのカードがシチュエーションカードでない**（選定時点で種類が分かれているため通常は到達しないが、実装の取り違えに対する多層防御として明示的に検証する）
3. 誤答3件・正解（最善の対応）の4件が、正規化後（`normalize_for_vocab_match`）にすべて異なるわけではない（重複がある）
4. 各誤答の文字数が、正解の文字数に対し`vocab.situation_distractor_min_length_percent`〜`vocab.situation_distractor_max_length_percent`（既定50〜150%）の範囲内にない（極端に短い・長い誤答が消去法のヒントになることを防ぐ、F-U6）
5. 1回の生成で、同じカードIDを出典とする2問目以降（1枚のカードにつき1問まで）

採用されたブロックのみ`quiz_question`として保存する。`question_text`は「状況＋空行＋問い（または既定文言）」（`vocab_service.build_situation_prompt_text`）、選択肢は正解（最善の対応）と誤答3件をシャッフルしたもの、`explanation`は登録済みの解説（空の場合は「最善の対応は『（最善の対応）』です。」という文言、`situation_no_explanation_text`。`QuizQuestion.explanation`はNOT NULL制約のため空文字を保存できない）、出所は17.16と同じ`vocab_card_id`・`theme_id`=NULL・`citation_date`=NULLとする。

**解析の正規表現の安全性**：17.15・17.16と同じ共通モジュールの方針（`[^\n]+?`・`re.DOTALL`不使用・`_MAX_BLOCK_CHARS`）を新規の`_DISTRACTOR_BLOCK_PATTERN`にも適用する。敵対的な繰り返し入力でも1秒以内に完了することをテストで確認する。

**失敗耐性**：17.16と同じくデッキ単位で取り消して続行する。1デッキの処理内で、用語カード（17.16）・シチュエーションカード（本節）の両方を生成するが、いずれかの失敗で両方がロールバックされる（デッキ単位のコミット境界を1つに保つ、既存の失敗耐性方式を踏襲）。

**カード編集・削除・`use_in_ai`変更時の扱い**：30章（単語帳の判定・出題ロジック）を参照。シチュエーションカードは見出し・状況・問い・最善の対応・解説のいずれかが実際に変わったときに、そのカードの`quiz_question`を削除する（解説も`explanation`に保存しているため、用語カードの削除条件〈用語・意味・別名のみ、noteは対象外〉とは異なる）。

**出題・成績への反映**：17.16と同じ。単語帳由来の問題の出題・解答は、単語帳の問題集の成績（`vocab_answer_log`）には一切影響しない。

設定（既存のシードで未登録分のみ追加）：`vocab.situation_distractor_min_length_percent`（既定50）・`vocab.situation_distractor_max_length_percent`（既定150）。いずれも設定画面（SC-11）からの変更経路は設けない（内部パラメータとして扱う）。

#### 17.17.1 脅威モデル（STRIDE、スキル`threat-model`に従う）

本機能は、シチュエーションカードの自由記述文（状況・問い・最善の対応）を外部AI（NewtonX）へ送り、誤答3件を生成・永続化・表示する新規の経路である。信頼境界・データフローは17.16.1と同じ構造（利用者の入力→外部AI、AIの出力→保存・表示の2か所）。本アプリは単一利用者・ローカル運用のため、利用者間の権限分離は対象外。

| 脅威 | カテゴリ | 対策 |
| --- | --- | --- |
| 状況・問いの自由記述へのプロンプト注入 | T (Tampering) | 山括弧の全角化＋nonce区切りの二重防御（17.16.1と同じ）。根拠検証は行わない代わりに、AIが作る対象を誤答3つだけに限定することで、問題文・正解の前提そのものは注入の影響を受けない |
| 出典カードIDの偽装（存在しないID・用語カードのID） | T (Tampering) | 出典の実在検証に加え、出典カードが`card_type == SITUATION`であることを明示的に検証する（多層防御） |
| 誤答の長さによる消去法のヒント化 | T (Tampering) | 正解の文字数に対する比率判定（`vocab.situation_distractor_min/max_length_percent`）で範囲外の問題を破棄する |
| 改行による「1行形式」の構造偽装 | T (Tampering) | `flatten_for_single_line`で状況・問いの改行を半角空白へ変換してから埋め込む（17.16.1と同じ） |
| 状況・最善の対応の本文の漏洩 | I (Information Disclosure) | AIへの注入経路（17.17本文）とは別の経路（日次フィードバック・目標相談、要件C）では見出しだけを渡す（R-205）。本節自体は状況・最善の対応をAIへ送るが、これは正規の生成経路であり漏洩ではない |

**受容したリスク**：シチュエーションカードの内容は利用者本人の入力（既存のAI機能全般と同じ受容済みリスク）であり、本機能固有の追加の情報開示リスクは無い（単一利用者ローカル運用のため、他者への漏洩経路が無い）。
