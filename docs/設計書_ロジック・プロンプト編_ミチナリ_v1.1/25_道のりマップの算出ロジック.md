## 25. 道のりマップの算出ロジック

本章は、目標ごとの進捗を「スタート→現在地→ゴール」の図として可視化する「道のりマップ」（開発Todo「道のりマップ」v1.0、要件定義書6.17 R-126〜R-131、仕様書6.1.5・6.2・13.8）の算出ロジックを定義する。算出は`backend/app/services/roadmap_service.py`が担い、正規化された比率（0.0〜1.0）・日付のみを返す。SVG座標への変換はフロント側（`frontend/src/features/goal/roadmapGeometry.ts`）の責務とし、座標計算ロジックの重複を避ける（CODING_RULES.md①DRYの原則）。新しい値はDBに保存せず、既存テーブルから都度算出する（CLAUDE.md）。

### 25.1 共通

- 道標（AIフィードバックを受けた日）：`analytics_service.list_growth_descriptions`をそのまま再利用し、`record_date`の集合を返す（道標＝日次報告でAIフィードバックを受けた日。3種別共通）。AI未設定・フィードバック履歴が無い場合は空配列になり、道標なしで図が成立する（要件定義書R-129）。
- 道の引き直し目印・予備日・完了予測との乖離（`overrun_days`）は資格試験目標のみ算出し、読書・仕事目標は常に空配列／`null`を返す（25.2〜25.4、13.8の既定方針）。

### 25.2 資格試験目標（EXAM、山）

| 項目 | 算出 |
| --- | --- |
| 山頂の日付（ゴール） | 目標に紐づく全科目の有効受験日（`material_service.effective_exam_date`）の最大値（最も遅い日）。要件文言「全科目の受験を終える日」に基づく新規算出であり、ダッシュボードの`_goal_remaining_days`（最も近い受験日を使う別目的の算出）とは別の値である |
| 標高（進捗比率） | 教材ごとの全周回進捗率（`metrics_service.compute_progress_rate(cycle_service.get_material_progress(...))`、既存の`total_work = total_amount × planned_cycles`を前提とする周回対応済みの値）の単純平均。2周目・3周目の教材も標高にそのまま反映される（周回ごとの区切り線等の追加表現は本機能のスコープ外） |
| 計画線 | 教材ごとの`analytics_service.compute_plan_line`の結果を、教材の総作業量で比率化したうえで日次のステップ関数へ変換し（記録・計画が1件も無い日は直前の値を保持）、目標全体の日付範囲（開始日〜山頂またはゴール超過後の本日のうち遅い方）へ延長してから、教材間で日次に単純平均する |
| 実績線 | 教材ごとの`cycle_service.compute_cumulative_progress`を同様に比率化・延長・平均する |
| 道の引き直し目印 | `goal_service.get_baselines`（`PlanBaseline`）のうち、`BaselineReason.INITIAL`（初回の計画）を除いた各時点。目印の比率は「基準値設定時点の残量」から逆算した完了比率とする |
| 予備日 | `calendar_service.resolve_day_types`が`DayType.BUFFER`を返す日（13.5・13.8の既定方針により資格試験・読書目標が対象。本機能の初版実装では資格試験目標にのみ適用しており、読書目標への適用は25.5の既知の課題を参照） |
| 完了予測との乖離（`overrun_days`） | 教材ごとの`speed_service.compute_forecast_date`が返す乖離日数の平均（存在する教材のみ。未算出の教材のみの場合は`null`） |
| 現在地到達（`is_achieved`） | 標高（進捗比率）が1.0以上 |

### 25.3 読書目標（READING、地図上の道）

| 項目 | 算出 |
| --- | --- |
| 道の長さ・現在地 | `DailyRecord`と`ReadingLog`を日付昇順で結合し取得。`current_page`が入力されている行を実績点（比率＝現在ページ／総ページ数、1.0を上限にクランプ）とし、最後の実績点の比率を現在地の進捗比率とする |
| 足跡 | `current_page`が未入力の記録日（記録はあるが定量入力が無い日）を、比率を持たない足跡として置く。フロント側（`roadmapGeometry.ts`）が直前の実績点の比率を引き継いで道の上の高さを決める |
| 計画線 | 開始日（書籍の読書開始日）からゴール（読了目標日）までの日数按分の直線。ゴールを過ぎた日は1.0のまま延長する |
| ゴール（終了日） | 書籍の読了目標日（`book.due_date`） |
| 道の引き直し目印・予備日・`overrun_days` | 計画基準値の概念が読書目標には設計上存在しないため（データ構造編5.3）、道の引き直し目印は常に空配列。予備日・`overrun_days`は13.8参照（予備日は25.5の既知の課題により本機能の初版実装では未反映） |
| 書籍未登録（下書き中） | 開始日のみを持つ空の道として成立させる（境界ケース：記録0件と同様） |

### 25.4 仕事目標（WORK、評価期間の終わりまでの足跡の積み上げ）

| 項目 | 算出 |
| --- | --- |
| 道の起点・終点 | 現在の評価期間（`work_report_service.default_semiannual_period_key`／`semiannual_period_range`、3〜8月＝H1、9〜翌2月＝H2）の開始日・終了日。目標の開始日（`goal.start_date`）や案件の着手日（`work_assignment.start_date`）は使わない。資格試験・読書と異なり「決まった量のゴール」が無いため、評価期間そのものをゴールとする（要件定義書R-126） |
| 進捗比率（現在地） | 評価期間に対する経過日数の割合（`(本日 - 開始日) / (終了日 - 開始日)`、0.0〜1.0にクランプ）。計画線と比較すべき「進捗量」の指標が存在しないため、計画線・実績線は常に空配列とする |
| 足跡 | 当該評価期間内で、案件の`WorkLog`に紐づく記録がある日 |
| 現在地到達（`is_achieved`） | 本日が評価期間の終了日以上（評価期間は常に本日を含む期間として算出されるため、「ゴール超過」は構造的に発生しない） |
| 道の引き直し目印・予備日・`overrun_days` | 25.1・13.8参照。いずれも常に空配列／`null` |

### 25.5 既知の課題（2026-10-30）

本機能の初版実装は、予備日（UI-07）を資格試験目標にのみ適用し、読書目標には適用していない（`roadmap_service._reading_roadmap`が`buffer_dates`を常に空配列で返す）。これは仕様書13.5の既定方針（資格試験・読書目標に表示、仕事目標は対象外）との不整合であり、`_buffer_dates`を読書目標にも適用するよう、次の実装工程で修正する（開発Todo「道のりマップ」v1.0 §6参照）。

### 25.6 脅威モデル（STRIDE、スキル `threat-model` に従う）

本機能は読み取り専用で、新しい外部入力・外部システム連携を持たない。データフローは「利用者（開発キットで認証済み） → `GET /dashboard`（既存拡張）／`GET /goals/{id}/roadmap`（新規） → `roadmap_service`（既存テーブルの読み取りのみ） → DataStore（新規保存なし）」。信頼境界はブラウザ↔ローカルFastAPIサーバ間（社内限定・単一利用者のデスクトップ運用、CLAUDE.md前提）。

| 脅威 | カテゴリ | 対策 | 実装箇所 |
| --- | --- | --- | --- |
| 未認証でのAPI呼び出し（なりすまし） | S | 既存の認証依存関係（Depends）を新規ルーターにも付与（既存の`goals`ルーターへの相乗りのため自動的に適用済み） | `app/api/goals.py` |
| 存在しない／他の`goal_id`を指定した改ざんされたリクエスト | T | 既存の目標取得パターン（存在確認→`NotFoundError`→API層で404変換）をそのまま使用 | `goal_service.get_goal`、`app/api/goals.py:get_goal_roadmap` |
| エラーメッセージからの内部情報漏洩 | I | 既存のドメイン例外→HTTPエラー変換パターンを踏襲（内部スタックトレースを返さない） | 既存の例外ハンドラ |
| 道標クリック先（日次報告閲覧）での越権表示 | I | 日次報告閲覧（SC-08、`ROUTES.dailyReportView`）は既存ルート・既存権限チェックを流用し、新規リスクを増やさない | `frontend/src/features/goal/RoadmapDiagram.tsx` |
| 複数教材・長期目標での計画線合成計算の計算量増大（DoS） | D | 日次ループの計算量を教材数×日数の線形に留め、`GET /dashboard`の2秒要件への影響が無いことを確認済み（縮小版は既存の`progress_rate`・`forecast_deviation_days`を再利用するのみで新規DBクエリを追加しない） | `roadmap_service.py`、`app/api/dashboard.py:_resolve_roadmap_summary` |
| 権限昇格 | E | 該当なし（ロール区分なし、単一利用者前提） | — |

**受容したリスク**：なし（読み取り専用・新規データ保存なしのため、本機能固有の残存リスクは認めない）。
