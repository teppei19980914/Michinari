## 20. 検証仕様（テスト観点）

以下は実装時に単体テストで検証すべき観点である。

| 分類 | 検証観点 |
| --- | --- |
| 境界時刻 | 境界時刻より前の時刻において論理日が前日になること |
| 境界時刻 | 境界時刻が0の場合、システム日付と一致すること |
| 日種別解決 | 個別指定が祝日および曜日既定より優先されること |
| 日種別解決 | 祝日の扱いが設定値に従って切り替わること |
| 周回 | 1周目完了時に残量が0にならず、2周目のノルマが算出されること |
| 周回 | 現在周回が累積完了量から正しく導出されること |
| 周回 | 予定周回数を完了済み周回数未満に変更できないこと |
| 周回 | 予定周回数の変更で基準値が再設定されること |
| 日次ノルマ | 7日連続未達時、全量繰越（8倍）ではなく再配分（約2.2倍）になること |
| 日次ノルマ | バッファ日のノルマが0になること |
| 日次ノルマ | 負荷係数を変更しても総量が保存されること |
| 日次ノルマ | 残計画日が0の場合に例外が発生しないこと |
| 実効速度 | 周回ごとに分離して算出されること |
| 実効速度 | 現在周回のサンプルが3件未満のとき直近周回の値で代替されること |
| 実効速度 | 時間未入力の実績が分母・分子とも除外されること |
| 実効速度 | OFF日の実績が除外されること |
| 実効速度 | 実績が存在しない場合に算出不能として扱われること |
| 完了予測 | バッファ日が累積対象から除外されること |
| 完了予測 | 反復上限で打ち切られること |
| 判定 | 警告倍率および超過日数の閾値が設定値から読まれること |
| 判定 | バッファ日に警告判定が行われないこと |
| 基準値 | リプラン後に新しい基準で警告判定が行われること |
| スロット | 環境タグと必要連続時間による適合判定が正しいこと（必要連続時間はスロットの連続時間ではなく配分時間と比較すること） |
| スロット | 適合するスロットが存在しない場合に警告が出ること |
| スロット | あるスロットへの配分の合計がそのスロットの連続時間を超える更新がRESOURCE_EXCEEDEDで拒否されること |
| スロット | スロットの短縮・削除により既存の配分が超過しても保存が拒否されず、警告が返ること |
| スロット | スロットを削除しても、そのスロットで記録済みの実績の合計（minutes_spent）が変化しないこと |
| スロット | 分から時間への表示換算が四捨五入ではなく小数第2位以下の切り捨てになっていること |
| 実績 | 教材のminutes_spentが時間枠別入力の合計と一致すること。全欄未入力の場合はNULLとなり0にならないこと |
| 実績 | 配分していないスロットを追加して実績を入力できること |
| 実績 | 日次報告での時間枠別入力の変更がgoal_slot_allocation（マスタ）を変更しないこと |
| 状態遷移 | 確定済み記録への更新が拒否されること |
| 状態遷移 | 前日を超える遡及入力が拒否されること |
| 状態遷移 | 進捗のみ登録から報告への昇格が前日以内に限定されること |
| 状態遷移 | リソース不足時に一時停止からの復帰が拒否されること |
| 品質指標 | 主観的手応えが正しく正規化されること |
| 品質指標 | 周回別に系列が分離されること |
| 週次要約 | 未起動期間があっても遡及して生成されること |
| 週次要約 | 遡及上限を超えて生成されないこと |
| AI連携 | Web検索が明示的に無効化されて送信されること |
| AI連携 | 会話識別子が保存され、再利用されること |
| AI連携 | 親メッセージ順序が同一会話内で増加すること |
| AI連携 | 呼び出し間隔の下限が守られること |
| AI連携 | プロンプトが閾値超過時に段階的に縮退すること |
| AI連携 | 縮退の発生がログに記録されること |
| AI連携 | AI呼び出し失敗時に実績入力が失われないこと |
| AI連携 | AI応答なしでも報告確定が可能なこと |
| エクスポート | 選択した項目のみが出力されること |
| エクスポート | 匿名化時に日記本文が除外されること |
| エクスポート | JSON出力をインポートして復元できること |
| 読書 | reading_logが(daily_record_id, book_id)単位で一意登録されること |
| 読書 | 週次要約の生成対象からcategory=READINGの目標が除外されること |
| 読書 | category=READINGの目標がスロット配分の合計計算に算入されること（R-64。仕事とは扱いが異なる） |
| 読書 | リソース配分が未設定のcategory=READINGの目標を進行中へ遷移できること（配分は任意） |
| 読書 | reading_log.minutes_spentが実効速度・完了予測の算出に用いられないこと |
| 読書 | 1目標に2冊目の書籍を登録しようとするとBOOK_ALREADY_EXISTSで拒否されること |
| 読書 | GET /goals/{id}/planがREADINGで日次ノルマ等を返さず、残日数・直近記録日・連続記録日数を返すこと |
| 読書 | 連続記録日数（21.3）がバッファ日・除外日による中断除外を行わないこと |
| 読書 | 総ページ数を未入力のまま書籍を登録しようとすると拒否されること（R-70改訂） |
| 読書 | 現在ページが総ページ数を超える入力は拒否され、総ページ数ちょうどは受け付けられること |
| 読書 | 総ページ数を現在ページより小さい値へ引き下げられ、そのとき進捗率が100%にクランプされること |
| 読書 | 進捗率がNoneになるのは現在ページが一度も入力されていない場合だけであること |
| 読書 | DAILY_FEEDBACK_READINGのプロンプトにページに関する数値が含まれないこと（R-66改訂） |
| 仕事 | work_logが(work_assignment_id, daily_record_id)単位で一意登録されること |
| 仕事 | 週次要約の生成対象からcategory=WORKの目標が除外されること |
| 仕事 | category=WORKの目標がスロット配分の対象外であり、配分の更新が拒否されること |
| 仕事 | 1目標に2件目の案件情報を登録しようとするとWORK_ASSIGNMENT_ALREADY_EXISTSで拒否されること |
| 仕事 | 連続記録日数（22.3）がバッファ日・除外日による中断除外を行わないこと |
| 仕事 | 半期の期間判定（22.5）で、2月29日を含む閏年のH2期間（9月〜翌年2月）が正しく扱われること |
| 仕事 | 月次報告の生成時、前月分のgoal_retrospective（period_type=MONTHLY）が存在しない場合でもエラーにならず「前月の報告なし」として生成されること |
| 仕事 | 同一goal・同一period_type・同一period_keyで再生成した場合、新しいレコードが追加され、最新のgenerated_atのものが既定表示されること |
| 仕事 | `POST /goals/{id}/retrospective`（EXAM/READING専用）にWORK目標のgoal_idを指定するとVALIDATION_ERRORで拒否されること |
