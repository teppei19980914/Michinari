## 23. ヘルプAIアシスタントの生成ロジック（1.1改43、Phase43）

本章は開発Todo「ヘルプAIアシスタント」v1.0 の §4（処理フロー）・§5（禁止語）・§7（リスク）を設計として固定する。

### 23.1 処理フロー

1. **入力検証**：空・上限超過（`ai.help_question_max_chars`）を拒否する。制御文字（改行を除く）は取り除く。
2. **禁止語判定**：正規化（NFKC・小文字化・空白除去）後に、有効な禁止語（`ai_forbidden_term`）と照合する。該当すれば送信せず `UNAVAILABLE` を返す（ログには残さない）。
3. **ヘルプ本文の組み立て**：全文が予算内なら全文。超える場合は、質問の2文字の組との一致が下限（2件以上）のセクションを、一致の多い順に予算内で採用する。採用が0件なら送信せず `NOT_FOUND` を返す。予算は「`ai.max_prompt_chars` − 指示文の固定部分 − 質問」。
4. **送信**：質問ごとに新しいチャット（フォルダ `ai.help_folder_name`）を作る（`ensure_conversation`、スコープ `HELP_ASSISTANT`、スコープキーは乱数）。`send_and_log` で送信し、`ai_log` に記録する。区切りはリクエストごとの乱数（nonce）を用いる。
5. **後始末**：送信後（成否によらず）チャットを削除し、一覧で残っていないかを確認する。残っていればログに警告を残す（回答は失わない）。会話行は削除する。
6. **出典の検証**：回答末尾の `[出典: セクションID]` を読み、実在するIDのみ採用する。実在するIDが無い場合は `NOT_FOUND`。
7. **表示用の整形**：出典行を本文から取り除く。本文が上限（`ai.help_answer_max_chars`）を超える、または禁止語を含む場合は `UNAVAILABLE`。
8. **直列化**：質疑の処理全体をプロセス内のロックで保護する（単一端末のため）。

### 23.2 プロンプト

`prompt_template`（用途 `HELP_ASSISTANT`）に置く。変数は `{{help_body}}`（ヘルプ本文）・`{{question}}`（利用者の質問）・`{{nonce}}`（区切りの乱数）。

- 指示文は区切りの外に置く。利用者の質問は、乱数の区切りの中のデータとして扱うよう指示する。
- 回答は日本語・簡潔。最後の行に `[出典: セクションID]` を書く。記載が無い場合は `[出典: なし]`。
- 文面はコードに書かず、初期投入（`prompt_texts_common.HELP_ASSISTANT`）から `prompt_template` へ入る。

### 23.3 入力の安全性（テンプレート展開）

`prompt_builder` の変数展開は1回のパス処理で行い、値の中に現れた `{{...}}` を再展開しない（利用者の入力が別の変数として展開されない）。質問を区切りに埋め込む前に、山括弧（`<` `>`）を全角に置換する。

### 23.4 脅威モデル（STRIDE、スキル `threat-model` に従う）

本機能は、利用者の文章（質問）を外部AI（NewtonX）へ送り、回答を画面に表示する。データフローは「利用者 → 質問欄 → API → 禁止語・出典の検証 → NewtonX（質問ごとのチャット） → 検証 → 画面」である。信頼境界は、利用者の入力と外部AIの出力の2か所。

| 脅威 | カテゴリ | 対策 | 実装箇所 |
| --- | --- | --- | --- |
| 指示の上書き（「指示を無視」） | T | 区切り（乱数）の中のデータとして扱う指示、禁止語、出典の検証 | `help_assistant_service.py`、`prompt_texts_common.HELP_ASSISTANT` |
| 区切りの偽造 | T | 乱数の区切り、質問の山括弧の全角化 | `help_assistant_service.py`（`DELIMITER_REPLACEMENTS`） |
| テンプレート注入（`{{...}}`の展開） | T | 1回のパス処理による展開 | `prompt_builder._substitute` |
| 禁止語の回避（全角・空白・大小） | T | 正規化後の照合 | `normalize_for_match` |
| 出典の偽装・ヘルプにない機能の混入 | T・I | 出典IDの実在確認、不合格は`NOT_FOUND` | `_parse_answer` |
| 回答のHTML・スクリプトの実行（XSS） | T・I | 回答はMarkdown（生HTMLを解釈しない）で表示 | `MarkdownText`、`HelpAssistantAnswer.tsx` |
| 質問内容の漏えい（ログ） | I | 質問・回答は既存の`ai_log`の保持方針に従う。禁止語で止めた質問は記録しない | `ai_log`、`log.retention_days` |
| 過剰な送信（DoS・コスト） | D | 質問の上限300字、直列化、呼び出し間隔の下限（`ai.min_interval_seconds`）、記載なしは送信しない | `help_assistant_service.py` |
| 権限昇格（AIへの道具の付与） | E | AIには道具（操作・データ参照）を与えない。テキストの送受信のみ | 設計上の制約 |
| 削除されないチャットの蓄積 | D | 送信後に削除し、一覧で確認。残れば警告 | `_discard_conversation` |

**受容したリスク**：偽の出典が実在するIDを指す場合（指示の上書きと併発したとき）は、出典検証では防げない。禁止語・乱数の区切りと併用し、残存リスクとして受容する。

### 23.5 検証の基準

開発Todo §6 の基準（範囲内の正答率90%以上、範囲外の記載なし95%以上、過剰拒否5%以下、出典準拠95%以上、インジェクション成功0件）。結果は開発Todo §9 に記録する。
