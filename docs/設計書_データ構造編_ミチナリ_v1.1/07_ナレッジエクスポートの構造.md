**読書目標（category=READING）の場合**

`subjects`・`materials`・`quality_trend`・`replan_history`・`weekly_summaries`・`results` は出力しない（該当データを持たないため）。かわりに以下を出力する。`retrospective` は読了レポート本文を格納する（キー名は共通のまま流用する）。

```
{
  "book": {
    "title": "...", "author": "...",
    "total_pages": 320, "start_date": "...", "due_date": "..."
  },
  "summary": {
    "record_days": 0,
    "max_streak_days": 0
  },
  "daily_records": [
    { "date": "...", "recall": "...", "current_page": 0 }
  ],
  "retrospective": "..."
}
```

**仕事目標（category=WORK）の場合**

`subjects`・`materials`・`quality_trend`・`replan_history`・`weekly_summaries`・`results` は出力しない（該当データを持たないため）。かわりに以下を出力する。読書と異なり、月次報告・半期評価は期間ごとに複数件存在しうるため（要件定義書R-80「案件単位で生成」、6.11本文「定期報告型」）、単一文字列の`retrospective`ではなく配列`retrospectives`を用いる（対象goalに紐づく全`goal_retrospective`をperiod_type問わず含める）。

### 7.2 Markdown形式の構成

| 節 | 内容 |
| --- | --- |
| 1. 概要 | 試験名、受験日、学習期間、結果 |
| 2. 総括 | 総括レポート本文 |
| 3. 学習量 | 総投下時間、学習日数、報告率、平均時間 |
| 4. 教材構成 | 教材ごとの総量、予定周回、実績周回、所要時間 |
| 5. 品質の推移 | 周回別の品質指標推移（表形式） |
| 6. 計画の修正履歴 | リプランの日時、契機、変更内容 |
| 7. 週ごとの経過 | 週次要約の全文 |
| 8. 付録 | 日別実績（表形式） |

第6節が本エクスポートの独自性である。**どの時点で計画が崩れ、いつ修正したかという情報は、他の学習記録には存在しない。**

**読書目標（category=READING）の場合**

以下の節構成に読み替える。

| 節 | 内容 |
| --- | --- |
| 1. 概要 | 書名、著者、読了目標日、読書期間 |
| 2. 読了レポート | 読了レポート本文（要約、感じたこと・考えたこと・気づいたこと） |
| 3. 記録量 | 記録日数、最長連続記録日数 |
| 4. 付録 | 日別の想起記録（表形式） |

**仕事目標（category=WORK）の場合**

以下の節構成に読み替える。

| 節 | 内容 |
| --- | --- |
| 1. 概要 | 案件名、取引先・案件の呼称、想定業務内容、着手日 |
| 2. 月次報告・半期評価 | 生成済みの`goal_retrospective`（period_type問わず）を期間の新しい順に全件列挙 |
| 3. 記録量 | 記録日数、最長連続記録日数 |
| 4. 付録 | 日別の業務記録（表形式） |

### 7.3 匿名化の処理

| 対象 | 処理 |
| --- | --- |
| 日記本文 | 出力から除外する |
| AI対話履歴 | 出力から除外する |
| 週次要約 | 業務・家庭に関する記述を除外するようAIに指示して再生成する |
| 総括レポート | 個人的事情への言及を避けるようAIに指示して再生成する |

匿名化版の週次要約および総括レポートは、それぞれ別レコードとして保持する。元の版は削除しない。

**読書目標（category=READING）の場合**：「日記本文」は想起記録（`reading_log.recall_body`）に読み替えて出力から除外する。週次要約は存在しないため対象外。「総括レポート」は読了レポートに読み替え、同様に個人的事情への言及を避けるようAIに指示して再生成する。

**仕事目標（category=WORK）の場合**：「日記本文」は業務記録（`work_log.body`）に読み替えて出力から除外する。週次要約は存在しないため対象外。「総括レポート」は月次報告・半期評価（`retrospectives`の各要素）に読み替え、対象goalに紐づく全件を、それぞれ個人的事情への言及を避けるようAIに指示して再生成する。
