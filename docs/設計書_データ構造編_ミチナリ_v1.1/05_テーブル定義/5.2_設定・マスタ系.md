**アシスタント選定について（2026-08-23、実機確認済み）**

用途ごとに異なるアシスタントを既定値とする。全用途を単一のアシスタントに固定すると、要約向きのタスクと分析・提案向きのタスクの双方に同じ特性のモデルを使うことになり最適でないため、`get_assistants()`で取得できる説明文を根拠に用途別へ分離した。

| 用途 | 既定アシスタント | 選定理由 |
| --- | --- | --- |
| DAILY_FEEDBACK（日次報告フィードバック） | GPT-5.4（高性能） | 「複雑なタスクの整理や具体的な提案に適しています」。状況解釈・成長の指摘・具体的行動提案・計画提案という17.2の要求に合致 |
| WEEKLY_SUMMARY（週次要約） | Gemini 2.5 Flash（高速） | 「日常的な要約や調べものに適しています」。起動時に複数週分を逐次生成するため速度も重視 |
| DAILY_MESSAGE（今日の一言） | GPT-5.4-mini（高速） | 「回答速度が速く、情報整理や提案をバランスよくこなせます」。ダッシュボードで非同期表示される軽量な生成に適する |
| GOAL_RETROSPECTIVE（総括レポート） | GPT-5.4（高性能） | DAILY_FEEDBACKと同様、低頻度・高品質重視のため同一アシスタントを採用 |

**既知の非対応アシスタント（実機確認済み・使用しないこと）**

導入済み環境（`seraku-ex.newton-x.net`）で`get_assistants()`が返す一覧のうち、以下2件は`send_message()`が常に404（`ChatTableModel matching query does not exist`）で失敗することを確認済みである。カタログには残っているが実際には利用できない状態と見られる（廃止済みモデルの可能性）。

| アシスタント名 | 識別子 | 状態 |
| --- | --- | --- |
| GPT-4o mini（高速） | `13358019-9ed8-4578-8490-583804ef5c78` | 使用不可（404で確認済み） |
| GPT-4o（高性能） | `8d0bbf4e-79c1-4f9e-9e9a-a034b784b11a` | 使用不可（404で確認済み） |

設定画面（SC-11）でのアシスタント選択時、この2件を選択肢から除外する、または選択後に疎通確認を行い失敗時はエラーメッセージとともに再選択を促す実装とする。除外判定は**識別子（UID）**で行う。2026-10-01の実機確認で、名称（nameフィールド）が「GPT-4o mini」→「GPT-4o mini(高速)」のようにAI基盤側の都合で変動し、名称完全一致での除外判定が機能しなくなる事象を確認したため（`app/ai/client.py`の`_UNSUPPORTED_ASSISTANT_UIDS`）。将来的にこの一覧（UIDの対象自体）は変動しうるため、ハードコードした除外リストに依存せず、`send_message`失敗時のエラーハンドリング（AI_ERROR、再送・再選択の導線）で汎用的に吸収できる設計とすること。

認証トークンは本テーブルに保存しない。5.8を参照。

**resource_slot（時間スロット）**

| 列名 | 型 | 制約 | 説明 |

連続時間は `end_time - start_time` として算出する。保存しない。算出結果は**分（整数）**を正準の単位として扱い、時間（hour）はこの分から換算した表示用の値とする（仕様書6.3「時間の単位と表示規則」）。

**goal_slot_allocation（目標へのスロット配分）**

| 列名 | 型 | 制約 | 説明 |
| --- | --- | --- | --- |
| goal_id | INTEGER | PK（複合）, FK → goal.id (CASCADE) | — |
| slot_id | INTEGER | PK（複合）, FK → resource_slot.id (CASCADE) | — |
| minutes | INTEGER | NOT NULL | このスロットから本目標へ割り当てる時間（分）。0以上 |
| created_at | DATETIME | NOT NULL | — |
| updated_at | DATETIME | NOT NULL | — |

**制約**

- 各 `slot_id` について、`status` が ACTIVE の goal の `minutes` の合計が、そのスロットの連続時間（分）を超えないこと。アプリケーション層で検証する（要件定義書R-07、仕様書NT-04）
- **この合計計算に `category=WORK` の goal を含めない**（要件定義書R-74。仕事は自由な時間に行う活動ではないため配分の対象外）。`category=READING` は含める（R-64）
- PAUSED および CLOSED 状態の goal は合計計算に算入しない。ただし行は削除せず保持し、復帰時の要求値として用いる（仕様書7.1）
- スロットの短縮・削除により合計が連続時間を超える状態は発生しうる。この場合はスロット側の保存を拒否せず、警告のみとする（仕様書NT-09、要件定義書R-87）

配分が0分のスロットは行を持たない（＝行の非存在と `minutes = 0` を同義とする）。
