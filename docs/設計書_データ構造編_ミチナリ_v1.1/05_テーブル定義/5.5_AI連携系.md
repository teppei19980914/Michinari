### 5.5 AI連携系

**ai_conversation（会話識別子）**

| 列名 | 型 | 制約 | 説明 |
| --- | --- | --- | --- |
| id | INTEGER | PK | — |
| goal_id | INTEGER | NULL, FK → goal.id | 日次報告フィードバックは複数目標にまたがりうるためNULL可。今日の一言はACTIVEな目標が無い日のみNULL（それ以外は目標ごとに独立した会話を持つ、未決事項L-04） |
| scope | TEXT | NOT NULL | ConversationScope |
| scope_key | TEXT | NOT NULL | 用途内での一意キー（日付、週開始日など） |
| conversation_uid | TEXT | NOT NULL | AI基盤側の会話識別子 |
| folder_uid | TEXT | NULL | AI基盤側のフォルダ識別子 |
| last_parent_order | INTEGER | NOT NULL, DEFAULT 0 | 直近の親メッセージ順序 |
| created_at | DATETIME | NOT NULL | — |

**制約**：`scope` と `scope_key` と `goal_id` の組み合わせは一意とする。

**設計意図**

AI基盤側では、メッセージ送信前に会話を作成し識別子を得る必要がある。この識別子をローカルに保持することで、一覧取得APIによる検索を回避する。

`last_parent_order` は、同一会話内で複数回のやり取りを行う際にAI基盤へ送信する値を記録する。日次報告における複数往復がこれに該当する。**ただし導入した開発キット（NewtonX ADK v0.10.5）では、この値を実際の文脈維持には利用できないことをソースコード確認済み**（`send_message()`に当該パラメータが存在せず常に固定値0が送信される）。同一日内の文脈維持は `chat_message` テーブルの対話履歴をプロンプトへ全文注入する方式（設計書 ロジック・プロンプト編 16.3.1、17.2の`{{conversation_history}}`）で実現する。本列は将来の開発キット改修に備えた記録として残す。

`scope_key` の値は用途により以下とする。

| scope | scope_key |
| --- | --- |
| DAILY_FEEDBACK | 対象日（YYYY-MM-DD） |
| WEEKLY_SUMMARY | 週開始日（YYYY-MM-DD） |
| DAILY_MESSAGE | 対象日（YYYY-MM-DD） |
| GOAL_RETROSPECTIVE | 固定値（"main"） |
| DAILY_FEEDBACK_READING | 対象日（YYYY-MM-DD） |
| GOAL_RETROSPECTIVE_READING | 固定値（"main"） |
| DAILY_FEEDBACK_WORK | 対象日（YYYY-MM-DD） |
| GOAL_RETROSPECTIVE_WORK_MONTHLY | 対象月のperiod_key（"YYYY-MM"） |
| GOAL_RETROSPECTIVE_WORK_SEMIANNUAL | 対象半期のperiod_key（"YYYY-H1"／"YYYY-H2"） |
| EVALUATION_REPORT_WORK | 評価対象メンバーのwork_member.id（文字列化）。期間ではなくメンバー単位で会話を分離する |
| RECAP | 分類は"classify-{対象日}"。テーマ本文は"theme-{テーマID}"。テーマ未作成のテーマ（同一チャンクで初めて現れる名前）は、IDが無いため"theme-name-{テーマ名}"で識別する（起動時バッチの書き込みを、AI呼び出し後にまとめて確定させるため。CODING_RULES.md「AI通信とトランザクション」） |

WORKの月次報告・半期評価は、`goal_id`（案件単位、要件定義書R-80）と`scope_key`（対象期間）の組み合わせで会話が一意に定まる。期間ごとに独立した会話とすることで、前月・前半期の会話文脈が当月・当該半期のプロンプトに暗黙に混入することを避け、文脈の受け渡しは`goal_retrospective`から明示的に注入する変数（ロジック・プロンプト編17.9・17.10の変数一覧）でのみ行う。

**ai_log（AI通信ログ）**

| 列名 | 型 | 制約 | 説明 |
| --- | --- | --- | --- |
| id | INTEGER | PK | — |
| purpose | TEXT | NOT NULL | AiPurpose |
| conversation_uid | TEXT | NULL | 会話識別子 |
| request_body | TEXT | NOT NULL | 送信内容 |
| response_body | TEXT | NULL | 応答内容 |
| prompt_chars | INTEGER | NULL | 送信文字数 |
| was_truncated | BOOLEAN | NOT NULL, DEFAULT false | 縮退が発生したか |
| latency_ms | INTEGER | NULL | 応答時間 |
| error_type | TEXT | NULL | 例外種別 |
| error_message | TEXT | NULL | エラー内容 |
| created_at | DATETIME | NOT NULL | — |

`prompt_chars` と `was_truncated` を記録することで、入力上限の実測値を運用の中で把握できる。これは未決事項 O-01 の解消に直結する。

`app_setting` の `log.retention_days` を超過したレコードは、起動時に削除する。

#### ai_forbidden_term（1.1改43、Phase43、マイグレーション b8e4d1f7a3c9）

ヘルプAIアシスタントの禁止語。質問に含まれる禁止語は送信せず固定文言で返す。照合は正規化後（NFKC・小文字化・空白除去）に行う。

| 列 | 型 | 制約 | 説明 |
| --- | --- | --- | --- |
| id | INTEGER | PK | — |
| term | TEXT | NOT NULL、UNIQUE | 禁止語 |
| enabled | BOOLEAN | NOT NULL、DEFAULT 1 | 無効化すると照合に使わない（誤検出への対処） |
| note | TEXT | NULL | 分類の覚え書き |
| created_at | DATETIME | NOT NULL | — |

初期投入（`seed_data.INITIAL_FORBIDDEN_TERMS`）は汎用の語14件。既存テーブルの変更は伴わない（新規作成のみ）。

#### attachment（開発Todo「添付ファイル機能」v1.0、マイグレーション c02c4e8b1cf1）

利用者が登録した添付ファイル。goal_idを持たない共通プール（同一ファイルを複数目標の日次報告・目標相談チャットで使い回しても実体が重複しないようにするため、要件定義書R-115）。PDF原本は保存せず、抽出テキストのみを保持する（`backup_service.export_all_data`のJSON化でBLOB例外が起きない設計でもある）。

| 列 | 型 | 制約 | 説明 |
| --- | --- | --- | --- |
| id | INTEGER | PK | 登録順の連番 |
| file_name | TEXT | NOT NULL | 元のファイル名（表示用） |
| extracted_text | TEXT | NOT NULL | PDFから抽出したテキスト全文 |
| char_count | INTEGER | NOT NULL | 抽出テキストの文字数。登録時に1回だけ確定する不変値のため保存する（都度算出ルールは日次ノルマ等の可変集計値が対象であり、不変な文字数は対象外） |
| created_at | DATETIME | NOT NULL | — |

status列は持たない（抽出文字数が下限（既定50字）未満・上限（既定20,000字）超過・禁止語を含む場合は登録自体を拒否し、常に抽出成功したものだけを保存する）。

#### chat_message_attachment（開発Todo「添付ファイル機能」v1.0、マイグレーション c02c4e8b1cf1）

日次報告のAI対話（`chat_message`）での添付ファイル利用リンク。

| 列 | 型 | 制約 | 説明 |
| --- | --- | --- | --- |
| id | INTEGER | PK | — |
| chat_message_id | INTEGER | NOT NULL, FK → chat_message.id, ON DELETE CASCADE | — |
| attachment_id | INTEGER | NOT NULL, FK → attachment.id, ON DELETE CASCADE | — |

**制約**：`chat_message_id` と `attachment_id` の組み合わせは一意とする。

利用者の発言があるターンではUSER行、無ければASSISTANT行に紐づける。添付ファイルを削除すると本テーブルの行のみCASCADEで消え、`chat_message`本体（対話本文・応答）は残る（「どのファイルを参照したか」の情報だけが失われる安全弁）。

#### goal_consultation_log_attachment（開発Todo「添付ファイル機能」v1.0、マイグレーション c02c4e8b1cf1）

目標相談チャットの質問（`goal_consultation_log`）での添付ファイル利用リンク。列構成・削除時の挙動はchat_message_attachmentと同型（`goal_consultation_log_id`と`attachment_id`の組み合わせが一意）。
